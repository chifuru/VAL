# プロジェクト配置と Git 反映

- 入力: プロジェクト名のディレクトリを作成し、関連ファイルを格納してリモートへプッシュするユーザーの明示指示。
- プロジェクト名: hello-valis。
- Git ルート: /workspace/VAL。プロジェクトルート: /workspace/VAL/hello-valis。
- 主 FLOW: FLOW-05。補助: FLOW-08（移動後の実行証跡）、FLOW-12（利用手順）。
- 対象: src / tests / valis / operations の配置、利用手順、Manifest の検証接続。
- 承認範囲: 今回のローカル移動、コミット、origin の main へのプッシュ。
- 変更しないもの: 実装・テストの内容、Operation / Flow Definition の本文、ノードの草案状態。
- 前提: 既存ファイルと同名の移動先がないこと。移動時には全ファイルの SHA-256 が一致すること。
- 記述規則: 正本・ノード・実装・テスト・資料の相対パスはプロジェクトルート基準。
- 検証: プロジェクトルートから既存4テストを実行し、結果を新規 E 層証跡へ接続する。
- Manifest: 新規証跡を初期登録し、現行の検証対応を部分反映する。
- Git: 関連ファイルだけをステージし、差分・内容を確認してコミット。force push は使用しない。
- 反映確認: main のリモート SHA とローカルコミット SHA の一致、作業ツリーの状態を確認する。
- 未実施範囲: GAS へのデプロイ・公開・実環境確認。Git push は GAS デプロイではない。
