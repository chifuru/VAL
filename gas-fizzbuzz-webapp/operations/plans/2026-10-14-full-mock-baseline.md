## 3. 実装対象14系統と造形の扱い

既存エンジン上の14系統ID:
- 旧12: abyss / myth / recursive / sail / gravity / crystal / manyeyes / abyssshell / parallel / memory / serpent / solar
- 新2: antimeme / valis

共通原則:
- 第一相は未分化体。第二/第三相は環境履歴・餌による分岐であり、系統を強制代入しない。
- 共通する頭部輪郭・眼配置・胴体比率・尾根元・色傾向を同一個体の継承要素として保持。祖先全身を後期肖像へ安易に重ねて「生物2体」にしない。
- 新2系統は不変身体2画像＋独立11器官×3Lvの33画像を合成する既存方式を保つ。旧12系統の第二/第三相24肖像は**暫定画像**であり、まだ「真の部位Lv別画像」と称さない。
- 系統・相・器官Lvごとの画像は、実際の画素・透明アルファ・接続位置・輪郭・前後レイヤー・過去相の継承を確認する。全モックの単純な切貼りだけで品質達成とはしない。
- UIは暗色の観測端末風、主肖像の高い優先度、成長器官、進化履歴、系統図鑑、FizzBuzzログ、環境刺激と入力操作を保持。PCと小画面で意味・操作・視覚階層を確認。

## 4. 変更禁止の実装契約

- Code.gsのGASサーバーを出力の正本とし、整数N=1〜1000に対して正確にN個の文字列を返す。15の倍数FizzBuzz、3の倍数Fizz、5の倍数Buzz、それ以外は十進整数（優先順保持）。
- 再生の一時停止・スキップ・速度・低モーションは元のN件出力を変えない。不正なGAS応答をローカル生成値に黙って置換しない。
- 同じNはDNA6軸を決定的に生成し、実行中も不変。環境刺激と餌の履歴で通常ルールに従って相入口で進化先を確定。交差進化・前相の器官継承を維持。
- 暫定の成長境界P=10/35/100を変更しない。P=100到達後は外見固定、FizzBuzz出力はN行目まで継続。第4相は名称候補だけで、発現条件・解放・描画を実装済み扱いしない。
- valis/coreの3中核定義、既存36承認済みノードの形式上の状態、過去版のE1〜E13の証跡、モック原本、旧Index.pixel-legacy.htmlを、この基準固定工程では変更しない。GASデプロイ・公開・権限変更は実施しない。
