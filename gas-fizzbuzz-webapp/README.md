Google Apps Script のHTMLサービスで動く FizzBuzzウェブアプリ。入力整数 **N全体** を初期生物のシード（遺伝子）とし、FizzBuzzの各出力に対応する4種の餌で、3つの相で育成します。次期試作では、進化系統をDNAの初期値ではなく育成中の状況から決めます。

## 出力契約（最優先・変更禁止）

`src/Code.gs` の `calculateFizzBuzz(N)` は **1～1000の安全な整数** を受け、`1..N` の順に **文字列配列N件** を返します（15の倍数→FizzBuzz、3の倍数→Fizz、5の倍数→Buzz、その他→数字の文字列）。

画面の読み上げ・一時停止・再開・速度変更・スキップ・低モーション表示を含め、結果欄の最終文字列は **元の配列を `'\n'` で連結したもの** と常に一致します。生き物の状態・成熟・餌の説明は絶対に結果テキストへ追加しません。完全成熟しても **Nまで計算・再生を継続** します。

## 4種の餌と成長ロジック

| FizzBuzz出力 | 餌 | 効果 |
|---|---|---|
| `Fizz` | 青の栄養餌 | 栄養、体色に青成分 |
| `Buzz` | 黄の栄養餌 | 栄養、体色に黄成分 |
| `FizzBuzz` | 紫の特別な栄養餌 | 栄養、体色に紫成分 |
| 通常の数字 | 第4種の調節餌 | 数学的規則で次の栄養摂取を促進または抑制 |

すべての出力行は **排他的にちょうど1種類** の餌に対応します。FizzBuzzをFizz/Buzzに重複計上しません。栄養餌の3種比率で体色を混合し、調節後の有効成長ポイントに応じて体積・器官・模様が変わります。数字餌の数は栄養摂取数に直接足しません。

### 数字餌の数学的規則（暫定実装）

通常数字 `n` の `r3=n%3`、`r5=n%5` について、`(r3=1 && r5<=2) || (r3=2 && r5>=3)` は促進、その他は抑制。3または5で割り切れる値は数字餌ではありません。

**今の実装の具体化:** 最後に食べた数字餌の効果が、次に食べる栄養餌 **1回** に適用されます。その前に別の数字餌を食べたら新しい効果で上書きし、栄養を食べたら中立に戻ります。通常の栄養は1P、促進時1.25P、抑制時0.75P。以前に取得したポイントを減らしません。これは設計検証のための**暫定係数と持続規則**です。素数による強度調整は未実装の検討候補です。

## DNAと形態進化

入力数値N全体をseedとするxorshift32の決定的擬似乱数で、`body / appendage / senses / skin / aptitude / sensitivity` の6軸（それぞれ0以上1未満）のDNAを作成します。同じNから同じDNAが再現され、育成中のDNA自体は不変。異なる数値の生物が偶然似ることはあります。

初期個体は次期試作では◌未分化体ミナモルフ（旧承認版では魚）であり、栄養餌0、調節中立、中立色、相対体積1.0です。DNA由来の胴体比率・ひれ/尾・目・模様は、陸生段階では足や尻尾、宇宙段階では触角などの形態に引き継ぎます。初期の承認済み版ではCanvasの整数ピクセルでパーツを描きます。最新次期試作では64×64の整数ピクセル格子と色分けした器官により、高密度なドット描画を行います。

| 有効成長ポイント P | 進化段階・状態 |
|---|---|
| `P < 10` | 第一相・萌生（未分化） |
| `10 <= P < 35` | 第二相・変容（その相の入口で系統確定） |
| `35 <= P < 100` | 第三相・異相（その相の入口で系統再選択） |
| `P >= 100` | 第三相の**完全成熟**（外見固定） |

10/35/100は正式な最終バランス値ではなく、試作用の仮閾値です。旧版では進化先の具体形態をDNAと栄養比率・蓄積した調節効果から選んでいました。現在の未承認試作では、相の環境圧力と直近餌を主に用いて進化先を選びます。承認済み基準版の暫定分岐は流線系・装甲系・知性系の3系統です。今回の新試作では14系統の第二相・第三相まで描画と分岐を実装済みです。第4相は名称候補のみで、解放条件・本描画は未実装です。

成熟の瞬間に **種族・体色・体積・模様・器官** の外見を固定し、その後も餌の集計とFizzBuzz出力は進みます。小さなNなら魚・陸生動物のまま終了し、最終段階への到達を強制しません。

現行のNは「DNAシード」と「FizzBuzz計算の上限」の両方です。同じNは同じ餌履歴を生むため、スキップ/再生速度に関係なく同じ完成形を再現します。

## 初期個体の差・段階内成長・形態分岐（新改修）

**初期差を大きくするため**、入力NからのDNAを生成する前に32ビットのアバランシェ混合（Murmur型）を行い、隣接する整数でも似た遺伝子ばかりにならないようにしました。DNA6軸自体は変えず、魚の体幅・体高・尾びれの長さ・目と感覚器官などの輪郭へ大きく写像します。初回表示時は入力欄のデフォルトNから新生物を作り、再生開始前もNを入力し直すだけでプレビューを更新します。

**各進化段階に3系統の形態分岐を実装**。魚は流線型・装甲魚・知性魚、陸生動物は滑空型・甲殻型・二足型、宇宙生物は星雲遊泳型・軌道装甲型・Lispエイリアンです。分岐は**それぞれの段階へ入った瞬間**にDNA、栄養餌の比率、調節履歴、前段階の系統の組み合わせで決定し、段階内では固定します。進化した個体の結果カードに **「進化の系譜：魚種 → 陸生種 → 宇宙種」** を表示します（到達段階まで）。

**成長を目に見える形にするため**、3つの正式な進化段階それぞれに「稚体→幼体→成長体→発達体」の**4つの発達形態**を追加しました。身体の半径・尾/ヒレ/翼・甲殻・感覚器官・模様密度が各発達段階で増えます。これは第4の進化段階ではありません。成長形態1/4～4/4・現在の系統・個体番号を育成HUDに表示し、発達段階の切替では光のエフェクトが発生します。**100P完全成熟時の外見固定、FizzBuzz N行完走、4種餌の分類・係数は不変**です。

分岐の決定式や大きさは今回の調整可能な試作規則であり、実ブラウザでの視覚品質はまだ確認していません。

## 次期試作：進化前の姿を引き継ぐ形態連続性

以前の試作では、進化系統の選択は局所環境/直近の餌で変えられましたが、描画が新しい系統の形態へ突然切り替わり、旧相で育てた器官が見えなくなる問題がありました。

今回の対策は**分岐先の決定と身体特徴の継承を切り離す**ことです。系統はその時の環境で自由に再選択しつつ、各相を越える瞬間に旧appearanceの系統・体色・DNA形質・8種類の器官成長量を不変の`imprint`として保存します。最大2つ前の相まで`heritage`で持ち越します。直前の器官量の72%、さらに古い相の35%を最低値として、新しい身体でも特化器官が急に消えないようにします。

最新次期試作では、**未分化体の背びれ・深淵触手の触肢・神鳥の翼紋・再帰知性の枝角など12系統の器官**を、次の体幹へ接続する整数ピクセル部品として描きます。旧身体の画像を後ろに残すだけではなく、アニメーションが終わっても新しい姿に器官の名残が残ります。第一相→第二相→第三相の交差進化では、第一相と第二相両方の特徴が第三相の身体へ残ります。

最新次期試作では、旧姿と新姿を約**1100ms**で4×4ディザによりドット単位で切り替えます。相内発達tierは約**560ms**で同様に移行します。低モーション設定では動きの補間を省きますが、`heritage`による新しい身体の造形は維持します。スキップ・結果画面も同じ最終appearanceを使います。

主/副特化器官と元の体色・眼の特徴は継続させつつ、進化先は局所環境で自由に変えられるため、**「別系統に進んだのに同じ個体だと分かる」**描画を目標とします。今回の継承/Canvas移行処理はV8モックで検査していますが、実ブラウザ目視でこの品質目標を満たしたかどうかはまだ評価していません。

## 次期試作：状況で変わる進化系統と中立的な相名

**初期Nだけで進化先は決まりません。** DNAは身体形状と主/副特化器官の素質を決めますが、第一相の◌ミナモルフには系統が未確定です。各進化の入口（10P / 35P）で、その相の環境の累積値と直近12行の環境、直近12行の餌の種類を評価して進化先を確定します。**前相の種族を加点・継承条件にしない**ので、〰触手→🜂神鳥→λ再帰などの交差変容も可能です。

相の暫定名称は「第一相・萌生 / 第二相・変容 / 第三相・異相」。名前自体が魚→陸生→宇宙という一本道を強制することはありません。ただし**完全な自由骨格メッシュではなく、12の系統ごとに異なる手続き的ドット部品**による試作段階です。

育成UIには4つの状況操作ボタンを追加しました：

- **〰 潮流**: 触手系に適応しやすい環境
- **🜂 熱波**: 神鳥系に適応しやすい環境
- **λ 電磁波**: 再帰系に適応しやすい環境
- **◌ 虚空**: 深淵・再帰の両方の圧力に作用する混合的な環境

これらは**確定分岐ボタンではなく、環境圧力を蓄積する操作**です。環境刺激（その相全体の65%、直近12行35%）に加えて、直近の栄養餌の種類も進化先を決めます。ボタンの変更はそれ以後の行にのみ作用し、相を越えた時点で次の判定用の環境履歴を初期化します。結果画面には各相の実際の種族名・優勢刺激を「変容記録」に表示します。

FizzBuzzはNが変わっても全個体で同じ先頭行列を通るため、環境操作などの外部状況なしで多種多様な分岐が起きるとは主張しません。**同じNでも異なる環境操作で異なる結果を得られること**が今回の試作の要点です。低モーション表示とスキップでも、選択した環境およびそれまでの履歴を維持します。

DNA6軸は保持したまま、**8器官カテゴリ**（眼・触手・翼/ひれ・甲殻・脚/腕・発光・頭部・浮遊器官）の数値を導出します。**主特化・副特化器官は出生時に固定**され、成長量に応じて伸び方が強調されます。栄養摂取による色/成長P、3段階の10/35/100閾値、成熟時外見固定、FizzBuzz N行完走は従来通りです。

系統は初期Nと各段階への遷移時のDNA・餌比率・前段階の系統で決まり、**同じ段階の途中で系統が突然変わることはありません**。現在の系統マークと主・副特化は育成HUDへ、系譜は最終結果へ表示します。

今後の12系統のマーク候補は、✦光帆 / ◎重力環 / ◇結晶 / 〰触手 / ◉多眼 / ▣深殻 / λ再帰 / ∥並列 / ⛨記憶殻 / 🜂神鳥 / Ϟ多頭蛇 / ☼日輪。**最新版では12系統の第二・第三相について描画・分岐とも実装済み**です。第4段階は表示条件が未決定であり、実装していません。

## 描画品質と終了時の「今回の最終形態」

旧承認版では32×32の整数ピクセルパーツを利用していました。E6時点ではベジェ曲線等の描画を試しましたが、最新版は64×64の整数ドット表現に戻しました。

- **魚**: 横向きのシルエット、分かれた尾びれ、背びれ、腹びれ、えら、顔の前方の目。
- **陸生動物**: 歩脚・足先、胴体・尻尾、頭・耳や甲殻。DNA由来の尾や模様を引き継ぐ。
- **宇宙生物**: 大きな頭部と目、触角、腕、触手。流線・装甲・知性系統に合わせたパーツ。
- どの段階でもDNAと餌から決まる体形・色・模様・器官の差を維持し、再生中のCanvasと結果カードの肖像を同一の描画関数で生成します。

FizzBuzzを**N行目まで再生した時点**で、画面を**ゲームリザルトモード**へ切り替えます。育成パネルと出力ログの視覚的な主従を切り替え、ステージ中央に大きい「RESULT SCREEN」を表示します。肖像・個体番号・具体種族・到達段階・成長ポイント・成熟状態・体色・4種餌の内訳をまとめ、光輪と表彰台風の背景、CLEAR風の称号を表示します。**完全成熟の場合のみ「EVOLUTION COMPLETE / FULL EVOLUTION」**、未成熟でのN終了は「RUN COMPLETE / STAGE n REACHED」と区別します。

Nが小さければ魚・陸生動物の段階で終了しても、それを**今回の最終形態**として扱い、完全成熟したと誤表示しません。途中で完全成熟した場合は完成時の外見を固定しつつ、FizzBuzzはN行目まで継続します。

通常再生・スキップ・低モーションの結果画面は同じ育成結果に基づきます。終了後のFizzBuzzログは専用ボタンで開閉できます。ログの表示状態だけを切り替え、元のN行のテキストは保持します。「もう一度 育てる」ボタンで育成画面へ戻り、前回の結果は初期化されます。結果画面の情報をFizzBuzzの**元の出力テキストに挿入しません**。ゲーム用UIはCSS主体であり、成長演算は従来のN件完走を維持し、現在のCanvas2Dでは64×64のドット描画を使用します。従来32×32の旧パーツ関数は互換用に残しています。
