# UI・生態バランス完成へ向けた決定稿 v1

## 今回の決定

利用者の指示により、現行の基本設計・生物・背景・地形・観測方式を一旦の決定稿とする。ここからは新系統や新機能の発展を広げず、決定済み内容の実装差分を埋め、UIとバランスを完成させる。動きを見た後の発展・修正は別の変更単位として扱う。

正本は[仕様索引](README.md)のv1.3→v1.8。今回の決定は未実装の条件を取り消すものでも、現行製品2.3を完成品と認定するものでもない。既存NodeのID・親子・正式状態は変更しない。造形の採用と、生態能力の実装・検証・正式承認を分ける。

## 選択した造形

|対象|v5の採用番号|選択画像の役割|
|---|---|---|
|植物共生|05|柔らかい流動的な身体と、内部の共生体・光の配置|
|社会性生物（既存ID: swarm）|01|低い環状の胴と支持部・信号組織の配置|
|早成生物（既存ID: precocial）|08|薄い防護片を重ねた低く広い身体|

元図は[生物別比較v5](../creature-design-review-v5/README.md)。利用者の「社会生成物」「早生生物」「海外光合成体」は前後の候補名と番号に対応させ、社会性・早成・海生光合成体として記録する。新しい生物種の指示には解釈しない。

**実装用の絵は採用図をそのまま縮小・切り貼りしない。** 選択図は体の形・構造の基準とし、案出し前の[素材モック](../asset-mock-v1/README.md)、[場面モック](../scene-mock-v1/README.md)、[分岐モック](../branch-mock-v1/README.md)へ描線、材質、色、発光、身体の見え方を合わせる。モックのUI・背景込みの画像をゲーム盤面へ貼らない。

寄生v3は潮環P・葉環P・抑環Qの各A/B/C全方向を保持し、陸生v3は森冠・星冠を保持する。日輪分岐v2の確認も維持。寄生の造形数を、そのまま新しい寄生枠・新種数・感染能力へ変換しない。既存のP/Q付随関係を守る。

## UIの完成条件

- 生物・餌・資源・死骸・地形・P/Qの位置と関係が遠景でも分かり、近景・選択欄が同じセル/ID/ターンを示す。
- 採用した造形を元モックの雰囲気で表現し、年齢・相・枝・雌雄・階級・健康を混同しない。候補図が存在するだけで実装完了としない。
- 開始設定、停止/送り/続行、拡大・移動・選択、説明、最終保存・再生・失敗通知が動作し、表示操作が生態結果を変えない。
- 大盤面・狭い表示・資産読込前後・生物の重なりを実測し、見えない要素を読めると報告しない。

## バランスの完成条件

- 初期配置された主系統について、300〜500ターンの**全区間連続存続**を、各系統を配置した10条件中3条件を目標、最低1条件として確認する。初期に不在の系統を分母へ入れない。総計10試行だけでは各系統10条件の検査にならない。
- 出生・次世代の成熟・再出生、死因、採食、移動、競争、友好、P/Qの生活環/感染経路を別に計測する。末尾に1個体いることだけを繁殖集団の安定と呼ばない。
- 全系統同時存続は要求しない。征服・絶滅は許容するが、勝者/存続集合が毎回同じになる偏りを調べ、単一の結末だけへ固定しない。
- 無償補充、開始後の環境書換え、隠れた救済、有限収支の破壊で合格させない。宿主・餌・植物が維持される結果として寄生も維持される条件を目指す。
- 開発用初期値と未使用の確認用初期値を分ける。系統構成・配置・地形・初期数と収支を記録し、少数系統の合格を全系統版へ拡張しない。

## 今回実施する範囲

今回の区切りは採用案の記録、完成条件と実装差分の固定、製品2.3の調整前計測。実行契約は[UI・バランス完成段階](../../operations/plans/ui-balance-completion-v1.md)。ゲームコード・能力係数・製品素材の変更や、新UI/新モデルの完成報告は行わない。計測は後続調整の比較元であり、決定稿全体の合格を意味しない。
