# A/B 一括最適化（4.2.32）

既存責務の改善。実行契約: operations/plans/optimization-v4.2.32.md。

- 背景は既存の基本背景・環境別の分岐・境界/岸辺・地物の原画を使って組み合わせ、固定した区画と配置をキャッシュする。全組み合わせの画像を保存しない。準備中も完成済み背景を拡大/移動して表示し、再生中の画面側で背景の差分を生成しない。
- 遠景の記号デザインと各個体の所在・選択を保つ。完成画像/静止フレームを再利用し、近景は位置索引から可視範囲を取得する。生物の前後関係、地形の立体感、雌雄/年齢/相の差分を維持する。
- 陰影は事前データとし下に配置。外観の初回加工は待機時間に準備し、相/年齢/出生等で新しく必要になる画像にも適用する。
- 索引と差分判定を再利用し、一時配列/Map生成・可変世界の不要な複製を減らす。個体/ターンの集団化・省略はしない。乱数方式・生態結果を変えない。
- 50Tの関係集計の追加/期限切れを管理し、全ターン原値を保持する。CSV/JSON出力は画面と独立または分割処理。再生結果を暗黙保存せず、明示保存は新記録とする。
- 通常の500Tと1T約1秒の設計を保持。性能は初回と安定時、遠景と近景、盤面サイズ別に確認し、全端末で滑らかと自己認定しない。

## 実装の具体化

- 背景の原画は既存11素材と地物を共通部品として使う。高精細の固定4×4区画を重なり付きで組み合わせ、接続/陰影の固定アルファデータと合成画像を再利用する。全景画像は描画Workerで準備し、近景完成前にも使用する。全組み合わせのPNGを新規に描き起こす方式ではない。
- 接続アルファは1チャンネルで保持し、色付き作業領域を使い回す。画像96MiB/接続データ24MiBをキャッシュ目安にし、接続データが上限を超える場合は保持しない。処理中の一時領域やプロセス全体の上限ではない。
- 遠景の生産者/分解者は、個々の記号・年齢/寄生差・当たり判定を維持した静止画像を再利用する。主生物/一次消費者と確定行動は別に描画。記号16MiB/楕円8MiB/合成スプライト4MiBの上限を設ける。
- 近景は位置区画索引を使い、移動開始/終了位置を含めて候補化。固定した主体位置と奥行き順を再利用し、画面内の対象を落とさない。
- 原画の連結成分判定は、ラベルと探索キューの型付き配列を再利用する。同じ画素を保持する。待機中の画像準備は1回に1画像、既存画像の確認は小分けに処理する。
- 開始前に背景/外観の準備と先行計算を順に進め、競合を減らす。準備全体は60秒まで。説明等による明示的な保留時間を準備の経過時間から除外し、通常のマップ操作では停止しない。
- 通信では全フィールドの文字列化をやめ、比較用の値を保持して変更分だけ複製する。適用先のID索引と土壌の型付き配列を使い回す。全変異のdirty追跡を実装したものではない。
- 関係と関与率の50T窓は追加/期限切れを処理。栄養フレームは対象/供給元/作用別に一度分類し、必要IDの窓を増分管理する。エネルギーは同じ時系列順に加算し、丸め誤差を変えない。
- CSV/JSONは8行ずつWorkerに渡して出力する。Worker生成不可時も分割処理し、全履歴を一括で文字列化しない。出力開始後の新しいターンを出力済み扱いにしない。出力失敗は観察を停止せず再試行可能とする。
- 背景Worker失敗時は固定区画を待機処理で一つずつ合成して復旧する。通常経路のメインスレッド背景生成は行わない。

- 描画面のCSS寸法が小数でも、整数へ丸めた実ピクセルの全域を不透明な基底色で描き直す。静止表示と強制再描画の画素を一致させ、最下端だけアルファが蓄積しないようにする。
