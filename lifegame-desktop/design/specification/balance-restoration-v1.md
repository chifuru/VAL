# 生産者の群落化と系統別生存目標の復帰

## 1. 適用と優先順位

仕様版 `balance-restoration/1`。利用者が採用した「生産者の占有密度と栄養供給量の分離」「生産者のみ1マスに複数採食分の栄養を集約」「系統別生存目標の復帰」を定義する。A/B文書への反映段階であり、製品4.2.32の生態・UI・保存形式は未変更、目標達成は未判定。

本書は、旧仕様の「下層は集団化しない」を生産者について見直し、R1〜R6を一旦完成後へ送る条件と、R0だけによる生態面の完成判定を置き換える。500T制・存続窓150〜250Tは維持し、1000T制や300〜500T窓へ戻さない。通常画面は `observation-ui-v1.md`、表示負荷設定は `display-load-reduction-v1.md` を併用する。動作確認済みの旧版証跡を新モデルの合格へ流用しない。

責務は既存A1（目標）、A1.2（空間分布）、A1.6（栄養）、A1.7（共通単位）、B4（比較と同期）、B4.3（生産収支）、B4.4（群落と一次消費者の更新）、B5.2（説明）、B5.5（集計）に分担する。新Nodeや機械的な階層合わせは不要。繁殖・寄生・行動の既存責務は維持し、今回それらの数値を決定しない。

## 2. 生産者の単位

- 生産者枠の草本・苔・藻・植物プランクトン等は、同じセル・同じ系統の群落を一つの記録として扱える。複数株分を表すが、内部の株ごとの個体計算は要求しない。離れたセル同士の栄養を共有しない。
- 群落ID、系統、セル、成立時刻、成長相、生物量B、可食部と基部、E/M等の既存収支に対応する有限量を持つ。栄養量と生物量の換算・容量を版付きで定義し、同じ蓄えを複数の食事や成長へ二重計上しない。
- 主生物・一次消費者は個体扱いを維持する。P/Qの既存群体扱いも維持し、これらを生産者と一緒にまとめない。分解者や主生物の植物共生体・光合成型を、通常植物群落へ一括置換しない。
- 生産者の成立後経過と成長相は群落の代表状態として扱い、内部に存在する全株の年齢・雌雄を推定して作らない。動物の年齢成熟・子I相・幼体/成体/老齢と進化相の独立は変更しない。

## 3. 群落の分布・採食・再生

| 処理 | 要求 |
| --- | --- |
| 初期分布 | 陸水の適地、光、水分、土壌など既存環境量を使い、豊かな群落・疎らな群落・空白を作る。地形は固定、栄養と群落量は変動する。装飾植生と可食群落を区別する |
| 採食 | 実際に摂取した可食量だけ減らす。1回食べられただけで群落全体を消さず、残量を複数回の採食に利用できる。複数個体の採食は同じ在庫で競合調停する |
| 再生 | 光・水・土壌養分と、その場所の支持量・再生速度をもとに上限まで回復する。供給なしでは既存の合法な入力だけ、供給ありでは外部入力を別台帳へ記録する |
| 拡大 | 群落内の増量と隣接セルへの新規定着を別処理にする。回復力を上げたことだけで占有面積を無制限に広げない。新規定着の空き枠・適地・材料支払を定義する |
| 衰退 | 基部は通常の採食でほぼ途絶えない設計を維持し、基礎栄養の悪化・途絶、稀な環境要因で縮小・消失し得る。可食部0と群落消失は区別する |
| 見た目 | 量に応じた密度・大きさ・被覆を使う。描画上の株数を計算上の動物個体数にしない。既存絵柄・背景の自然さと生物の識別を維持する |

目標は「少ない占有マスでも必要な栄養が得られる」こと。生産者の高い生産力は許容するが、全セル配置、無限栄養、動物の無親補充、生存目標を満たすための自動救済は採用しない。群落容量・初期蓄え・再生量・分布は別パラメータにし、既定値と利用者の設定を保存する。今回は数値を未確定とし、比較で選ぶ。

## 4. 一次消費者と空間競争

一次消費者は利用可能な植物量、局所混雑、捕食圧を受けて、採食場所へ集合・移動・繁殖・減少する。群落の可食部が減れば次の餌場へ向かう経路を確認する。全域一様配置や全面占有を安定の代替にしない一方、空白を作るための強制死亡も追加しない。

確認する量は系統別個体数・占有率・利用可能な植物量・採食成功・出生/死亡・子の再繁殖。一次消費者の抑制だけで主生物の餌を失わせず、生産量/同化率/捕食量/再生余力と一緒に比較する。主生物の増殖も局所資源と出生費用・空き枠で評価し、無制限増殖を認めない。

## 5. 復帰するR1〜R6

数値と結果署名の定義は `ab-visual-ecology-v2.5.md` 22節を継承する。各試験集合内の件数であり、一般的な生存確率を保証するものではない。

| ID | 完成判断に用いる基準 |
| --- | --- |
| R1 基本生存 | 必要な餌・配偶者・宿主等を備えた低競争条件で、各主系統が10条件中8条件以上、150〜250Tを連続存続。出生→子の成熟→その子の繁殖を少なくとも1経路で確認 |
| R2 競争下の生存 | 初期配置した各主系統が混合10条件中最低1条件、目標3条件で150〜250T連続存続。各系統に500T残存例を少なくとも1条件持たせる。3/10は調整目標とし、最低合格と区別して報告 |
| R3 食物網の更新 | 基準混合10条件中7条件以上で、450〜500Tに主系統と生活を支える生産/採食/出生または基部再生の経路が機能 |
| R4 結果の多様性 | 同じ基準構成10条件で有効な終端結果3パターン以上、最多署名6/10以下。全滅/崩壊/計算失敗を有効パターンにしない |
| R5 寄生の経路 | 各Pの成熟・次宿主への伝播、Qの一次成熟移行窓への感染・実際の行動作用を各1例以上確認。探索群体の残存だけでは成功にしない |
| R6 創発 | 異なる現象3種類以上を観察し、そのうち2種類以上を別初期条件でも確認。固定戦略命令・初期密集・乱数移動だけでは認定しない |

全系統の永久共存・均等勝率は要求しない。一系統の征服も有効だが、常に同じ勝者/存続集合となる状態を避ける。主生物5〜7系統＋適合する特殊生物2〜3系統程度の試験群を分け、各主系統に担当群を割り当てる。全系統総当たりは行わない。P/Qは適合生活環のある試験で評価し、全試行の存続や主生物と同じ割合を要求しない。

長寿の初期個体が残るだけでは世代更新にならない。生産者については動物の親子繁殖を機械的に要求せず、採食後の可食部回復・基部維持・群落の更新/定着を合法な入力と結びつけて確認する。動物の無親補充なしの世代更新、寄生の生活環は別に確認する。R0は短期の疎通確認として残せるが、完成判定の代替にしない。

## 6. 集計・保存の単位

- 動物は個体数、生産者は群落数、P/Qは群体数を記録する。数のグラフ・円は「個体・群落・群体の記録単位の割合」とし、植物の株数比や生物量比と解釈させない。既定の主生物表示、全体/群/系統選択は維持する。
- 内外の円は同じ分母を用い、群落数を任意の株数へ換算して割合を膨らませない。短い単位注記を使い、通常画面に大きな説明欄を戻さない。
- 生物量ピラミッドは有限な群落Bを合算する。可食栄養量、群落の占有率、動物個体数は別の量として診断へ保持する。定義のないP/QのBを捏造しない。
- 群落の年齢/相集計を表示する場合は記録単位・代表状態を示し、個体年齢分布に見せかけない。非適用・未観測を0や成体へ補完しない。
- 全確定ターンの原値を維持し、モデル・集計単位・係数・供給/優遇設定の版を保存する。旧記録は旧単位のまま閲覧可能にし、旧個体モデルを新群落モデルと同じ署名で再生しない。

## 7. 確認・調整の順序

1. **基準を固定**：現行製品の版/ソース指紋、地形、参加系統、初期数/配置/年齢、供給/優遇と係数を記録。モードや盤面サイズの差は別集計にする。
2. **現状測定**：描画なしで製品と同じ計算を回し、無変更時に全501状態が一致することを確認する。単なる総数の近似モデルを合否判定に使わない。
3. **土台を調整**：群落の栄養量と面積を分離し、陸水の生産→一次消費者、死骸→分解→還元を確認。群落化の単独差分を比較してから分布/係数を変える。
4. **主生物を調整**：成熟・配偶探索・空き枠・費用・待機・子の生存/再繁殖を診断。食性、移動/代謝、捕食/非捕食戦闘、防衛/友好/庇護、渡河の到達不能を分ける。
5. **寄生を調整**：Pの宿主負担/排除、接触/死骸/捕食伝播と、Qの初期数・窓到達・行動作用を区別。Qの初期数をPに応じて減らす既存方針と整合させ、無制限補充や全期間感染に戻さない。
6. **候補を選定**：固定3条件で原因を分離し、有望な組合せのみ固定10条件へ。最終候補は調整に使っていない事前固定3条件でも退行確認。群/地形を混ぜて件数を水増しせず、未評価・失敗を残す。
7. **製品/画面へ照合**：選定計算をWorker/保存/再生へ接続し、描画なし結果と同じ条件で照合。UI改善は別差分で進め、設定→生成→開始/停止→選択→500T→保存/再生→再生成を確認する。

収支・占有・有限値・再現性は常に維持する。生存目標に合わせて寿命だけを延ばす、勝者を指定する、配置不能や失敗例を試験後に除外する調整は行わない。500Tを5〜15分、事前準備60秒以内という実測目標も維持する。図や係数の増加で操作が重くなっていないか小中大で測定する。現時点ではいずれも新モデルで未測定。

## 8. 後続へ渡す未確定値

群落容量・可食部/基部比率・再生速度・初期分布密度・一次消費者の出生抑制等は比較で選定する。利用者へ数値の一律指定を求めず、原因と候補の効果を示す。既存責務を超える新規分割、基準の再緩和、系統設定そのものの変更が必要な場合は、具体案を提示して確認する。
