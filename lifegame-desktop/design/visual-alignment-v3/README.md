# 遠景・近景の画面すり合わせ

製品2.3.0の描画は利用者の期待を満たしていない。今回の対象は画面案のみ。右の近景を目標の描き込みとし、左の遠景は地形を面と輪郭に整理して、分布と活動を優先する。ゲームコード・生態ルール・承認状態は変更しない。画像は目標を合わせる概念資料であり、実装画面や性能・存続検証ではない。図中の種名・配置・活動・距離目盛は説明例であり、生態モデルの変更根拠ではない。種名は既存カタログを正とする。

[同じ地点を遠景と近景で見る比較モック](overview-and-closeup.png)

## 遠景：配置と関係が読める観測地図

- 水系、森、開けた地面、岩稜を、落ち着いた面・輪郭・模様で区別する。生物や情報と同じ発光表現を背景に使わない。
- 主役は系統固有の輪郭＋色。植物は芽、菌は傘、小型餌は小さな虫形で区別する。寄生は独立した主役印にせず宿主に付随させる。
- 密集時は系統別の分布・密度と代表印を使い、選択地点を拡大すると個体へ戻る。これは表示の集約であり、複数個体を1個体として計算する変更ではない。
- 採食、移動、攻撃、防御などの「何をしているか」を、短い軌跡・相手への線・小さな作用印で示す。全個体へ常時文字を重ねず、主要な接触地点と選択対象を優先する。
- 表示する軌跡は確定した直近の移動。未来の経路や未確定の戦略を、実行済みの事実のように描かない。活動表示は切替できるものとする。
- 近景の範囲を枠で示し、同じ河川・岩棚・倒木がどこにあるか対応を追えるようにする。

## 近景：生き物の営みを発見できる景観

- 遠景の素材をそのまま引き伸ばすだけでは成立しない。地面、水面、水際、斜面、地物、生物、効果、説明を分けて描く。
- 元モックの幻想生物を使う。現実の動物へ置き換えず、位相・雌雄・分岐に応じた造形と、移動・採食・攻撃の確定モーションを組み合わせる。
- 大きな円盤に画像を載せた駒を避け、地面との接触影、水面の波紋、草の間から見える餌などで景観になじませる。
- 主役と同じマスの餌、宿主上の一次寄生、その上の高次寄生を区別する。主役の陰に完全に隠れる要素は、縁取り・半透明・選択時の展開で読めるようにする。
- 行為者と対象が分かる描写を優先する。餌を摂る対象点、移動方向、攻撃の相手、防御中の姿勢を見せる。行動名は確定した動作の説明であり、固定戦略モードを追加するものではない。
- 情報は浮遊・滞留するエネルギー。光源の色や粒子の流れで位置と広がりを見せ、背景の装飾光と区別する。高次寄生の紫輪と情報の水色光を混同しない。
- 選択個体の説明は補助欄に置き、景観を数値表で埋めない。理由や関係は実際に観測できた状態に限定し、架空の行動理由を生成しない。

## 画面の採否を見る基準

1. 凡例と地図を見て、地形・主役系統・餌・情報を色以外でも区別できる。
2. 注目した相互作用について、行為者・対象・動作を画面で追える。
3. 遠景の選択枠と近景が同じ地形・個体を指す。
4. 近景に描き込まれた地物が、移動や遮蔽の実際の状態と矛盾しない。
5. 画像の見栄えの確認を、実装可能性・再現性・性能の検証済み報告へ置き換えない。

## 今回の実行範囲

既存C8.1の画面責務内でFLOW-04修正案を整理し、参考画像と確認事項を置く。必要な参照のみManifestへ反映。新しいノード分割、src/tests変更、製品採用、状態遷移、E層の製品合格証跡更新は行わない。画面案の方向が合うか確認を受けてから、素材製造・投影/奥行・重複識別・動作表示の実装と性能検査へ接続する。
