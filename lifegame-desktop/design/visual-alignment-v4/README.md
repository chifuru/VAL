## 変更の中心

情報を削る対象は造形や装飾であり、要素の存在と位置ではない。遠景で一部の代表個体だけを描いたり、密集した個体を一つの生物として扱ったりしない。主生物・餌・情報/資源を各マス内の別位置に保持し、寄生は宿主に付く印で追えるようにする。

近景は同じ世界の局所を詳しく見る。生物が大きな駒の円盤へ載っている表現から離れ、地面・水面・地物・生物・作用をそれぞれ描く。木や岩、水面に隠れるものは輪郭、局所透過、選択マスの内訳で追う。図中の種名、個体ID、配置、行動は説明例であり、新しい生態仕様や実行結果にはしない。

## 遠景で全て描けるか

計算盤面の全要素を描画対象に含めることと、全個体の名前・状態・行動を同時に読めることは別の条件。

例として160×112マスを1000×700画素の地図へ収める場合、1マスは約6.25画素四方になる。各マスの存在を小記号で示す設計はできても、その寸法で20系統の詳細な造形や全ての行動文字が判読できるとは保証しない。

- 主役の位置と系統記号を描き、餌/情報/寄生は別位置や角印へ割り当てる。重なった結果、別要素が完全に上塗りで消えることを避ける。
- 強調する系統を選んでも、他系統の位置を勝手に欠落させない。手動で表示を切る場合は切った層を明示する。
- 文字は選択対象と接触地点へ優先して添える。任意のマスを指すと、主役・餌・情報/資源・寄生の全内訳を読めるようにする。
- 画面が小さく記号の識別限界を下回る場合、地図を無制限に縮小して「すべて読める」とは言わない。判読に必要な拡大、移動、補助欄を提供する。全盤面の存在表示と細部の判読を区別する。
- 実装前に、最小マス寸法、画素衝突、全要素の描画対象数と実描画数、選択マスとの対応を検査する。静止モックはその検査の代用にしない。

## 近景の位置対応

選択マスの主役と餌は同じマスの別枠。Pは宿主、QはPに付随する。情報と死骸は地形や生物と取り違えない印を持つ。描き込みで隠れる場合は輪郭や透過を使い、補助欄で対象を選ぶと元の位置が強調される。

二枚は同じ川の曲がりと地物を意図した概念図だが、別々に生成した画像なので、座標と個体の完全な一致を証明するものではない。実装では同じ世界データから両画面を作り、同じ個体ID・セル位置を保持する。現画像ではS1の寄生・餌の内訳が遠景と近景で一致していない。画面構成の検討用であり、この食い違いを生態仕様として採用しない。次の実画面検証では同じ検査用世界から両画面を作り、内訳の一致を必須にする。

## 実行契約

既存C8.1の責務内でFLOW-04修正案を整理し、参考調査と独立した二枚の画面案を作る。関連coreの出力前ゲート・Manifest反映を照合し、現在の画面確認先だけを更新する。新規Node分割、src/tests変更、製品への採用、状態遷移、E層の製品合格証跡更新は行わない。方向確認の後、描画範囲の欠落と画素限界を確認できる動く画面へ接続する。
