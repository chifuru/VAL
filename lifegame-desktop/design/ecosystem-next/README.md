# 生存競争・自然地形の次期調整

このディレクトリは製品2.2.0とは別の比較モデル。foundation/v2の収支・繁殖・寄生処理を基準とし、地形と友好判定だけを変更する。未採用・未達成の仕様を製品の機能として扱わない。

## A：判定を固定する

- 主役は5〜7系統から開始。植物・菌類・小型餌の6系統は食物網の基盤として別枠。特殊生物は寄生2系統＋高次寄生1系統を基本とする。配置できなかった種は「存続成功」や「絶滅」に数えず配置不成立として別記し、試行不足を補う。
- 当該主役が配置された独立初期条件10件を母数とする。目標3件以上、最低1件以上で300〜500ターンの全更新にわたり個体数が1以上。途中で絶滅してから再投入する救済は行わない。これは観測合格件数であり、母集団の確率保証ではない。
- 継続存続とは別に「繁殖継続」を測る。300〜500の間の出生、500時点の子孫、成熟した繁殖可能な組または単為生殖母体を記録する。最終の雄1体を安定した繁殖集団とは報告しない。真社会性は女王・働き手・貯精の有効性も確認する。
- 「安定3/10」の合格には継続存続に加えて、上記区間の出生・500時点の子孫・繁殖可能集団の3条件をすべて求める。「最低1/10」は継続存続の最低線とする。今回のpilotは連続存続と出生までを測る段階であり、安定の合格判定はまだ行わない。
- 100ターン未満の消失を早期絶滅として死因・初期配偶機会・生息可能面積と併記。任意の最低個体数補充や結果に応じた攻防補正はしない。
- 最終比較は固定1000ターン。各主役が少なくとも1条件で到達できることを別途目指す。500までの合格から1000の存続を推定しない。
- 優勢は主役個体数シェア60%以上、併せて総生体量を表示。無個体は崩壊として征服と区別する。優勢系統、存続集合、最大シェアを初期条件ごとに記録する。同じ勝者・集合の反復率を出し、単なる最終種数の最大化を目的にしない。
- 初期条件を先に固定し、調整用と未使用確認用を分離する。全20主役の登場回数を揃える。自然配置の偏りは許すが、片方の性だけ・移動不能地形の中など初期配置そのものの不成立は分ける。

## A/B：友好・競争

同系統は従来どおり非攻撃。異系統の相互非攻撃の候補として太陽系統solarと光合成系統kelpを1組だけ試す。友好でも資源・場所は競合し、別系統との交配、餌の無償共有、寄生免疫は発生しない。攻撃候補・危険評価・攻撃確定の3箇所で同じ対称判定を使う。敵から逃げる評価を友好相手へ誤適用しない。寄生の接触経路は友好を越えて残る。

## A/B：自然地形と描画

環境は初期値で固定、餌・個体は更新する。円周上に8領域を等配する方式を廃し、連続標高を生成し、priority floodで低地・排水先を求め、集水量から水路を定める。湿度は水辺距離と降水、温度は連続場と標高を用いる。海・浅瀬・河川・湿地・岩稜が隣接してつながる。全環境を等面積で無理に詰め込まない。

試作の優先排水は4近傍。地図の端が排水口。実河川の浸食・蛇行・地質を再現したモデルではない。生成後の生息可能面積を集計し、特定系統が配置不能になる条件を検出する。

遠景は彩度を抑えた地形、系統別シルエット、群の密度を表示し、個体更新は省略しない。近景は同じ座標の個体を拡大し、位相・雌雄・行動を読み取れる図像とする。主役と餌は別の位置に寄せ、寄生は宿主上の小印、高次寄生はその外周、情報は透明な浮遊光で区別する。背景を個体より高彩度にしない。グリッドは通常非表示。比較画像は画風の概念資料であり実ゲーム画面・存続実測ではない。

## 結果図鑑：確認済みの実装契約

最終結果1件に、初期値、正規化済み全設定、計算版と定義指紋、終了ターン、終了理由、最終系統別集計を保存する。途中の世界スナップショットを累積しない。通常の系統図鑑とは別の「観測記録」一覧にする。

通常実行で利用者が「終了して図鑑へ保存」を選んだ時、または全主役絶滅で終了したとき1度だけ記録。1000ターン到達は続行可能な区間停止のため途中保存しない。一時停止・アプリを閉じるだけでは最終記録を追加しない。同じ終了操作の二重保存を防ぐ。

記録からの再生は保存した初期条件から再計算し、元記録の終了ターンで停止する。再生中は目立つ「再生・記録なし」を表示。再生を再度実行しても、完走・中断・終了・アプリ再起動を含む全経路で結果登録しない。再生データから通常実行へ暗黙昇格しない。計算版・定義指紋不一致は再現不能として再生を止める。速度・拡大・観測対象は生態結果を変えない。初期条件を変更して試す場合は、再生とは別に新規実験を明示的に開始する。

保存失敗は元の完了結果を失わせず通知し、破損記録は隔離表示する。ローカル保存であり外部送信しない。保存先・上限・削除操作は実装責務分割の確認後に既存デスクトップ保存方針へ接続する。
