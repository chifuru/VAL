# CS06：更新対象と固定環境の時間処理

対象 `current-state-activity/1`。起点0f7d320。[current-state/1](../specification/current-state-aggregation-v1.md) 8節を既存C7/C7.1/C7.2/C8.2、D7/D8/D9へ接合する。新Node/正式状態変更はない。

## 現在値と時計の方針

明示 `currentStateModel: "current-state/1"` の内部比較のみ。`current-activity.js` が現在の更新候補・固定入力の合計・直近の処理件数を保持する。過去Tごとの候補列や失敗履歴は残さない。

水分/養分の実在庫は引き続き `cellState.water` / `tiles[].soilM` が所有する。表示/在庫の参照で時刻を進めない。値を古いまま隠して後から物質を生成する方式ではなく、平衡で変化しない部分を更新待ちへ移す方式を採る。変化する固定入力は、生物のいないマスでも毎T反映するため、後から進入した個体も確定Tの現在値を利用できる。

気候変更やターンの省略は追加しない。固定環境はマップ初期化時の正本を使う。将来環境を再設定する場合は対象索引/固定フローを再構築する必要があり、今回の固定環境キャッシュを無条件に使い続けない。検証用に在庫を直接変更する場合も、実処理と同じ変更通知を行う。

## 水分の更新候補

初期化時に既存の一段更新式を照合し、非平衡のマスだけを `waterDue` に登録する。各Tでは候補にだけ同じ雨/固定流入→排水→蒸発を適用し、丸めも維持する。次の一段でも値が変わらなくなれば候補から外す。

平衡マスの入力・排水・蒸発は固定環境から求まるので合計値へ持つ。各Tの観測フローはその合計と実更新マスのフローで構成し、平衡に達したという理由で雨や排水を消さない。平衡へ移った当該Tのフローと、次T以降の固定フローを分け、二重加算しない。

光合成/分解等が実際に水を消費したときは、そのマスを一度だけ更新候補へ戻す。繰り返し通知でも候補/固定フローを重複変更しない。水域条件が未解決のマスを、最適化によって勝手に解決した扱いにしない。

## 養分入力と保持待ち

初期化時に正の `mineralInput` を持つマスだけを登録する。既定0なら全マスへの入力試行は不要。正の入力は実際に現在量を変える対象として処理し、土壌に入らない分は既存の有限なM保持待ちへ渡す。外部入力の各T台帳と収支を維持する。

満杯の保持待ちは毎Tに再試行しない。実際の無機養分取得で生じた変更、新しい待機在庫と現実の空きによって `mineralDirty` を更新する。次の準備時だけ該当セルの現在の空きを確認し、入る量を一度だけ還元する。空きがなければ再び待機し、正の量を消去したり同Tの新しい栄養として使ったりしない。

候補の索引は世界の外に置き、同じセルを重複登録しない。待機在庫全体の削除用走査も、実際に空になった在庫がある場合に限定する。非ゼロ入力で在庫量が増えること自体は、無効な試行とは区別する。

## 有機物と腐敗負荷

現在利用できる新鮮/分解中在庫をマスごとにまとめ、活動条件を同マス内で共有する。乾燥・温度/pH等で活動0の場合は、マス単位の条件確認だけで在庫ごとの分解/再配分を省略する。水分が回復すれば、空所でも次の背景段階から再開する。残存物を生体の不在だけで凍結しない。

腐敗負荷は、現在の在庫による負荷のマスと、直前に負荷を持ったマスの和だけを更新する。元の発生源が消えたマスを0へ戻し、全盤面の配列を毎T作り直さない。背景分解/熱/次T養分還元・有限在庫はCS03の規則を維持する。

生物・情報・卵/P/Qの生活処理と期限は、現行の実対象/現在状態に対して継続する。移動/出生/消失や感染体の残存を、主生物のいるセルだけへ制限しない。全対象の一律時間飛ばしや、新しい汎用イベントシミュレータは導入していない。

## 確定と観測

`activitySummary` は更新候補数と、当該Tの水分/養分セル・保持待ち試行・有機物マス/在庫・腐敗負荷マスの処理件数を示す。確定直前の土壌統合/保持待ち増分も反映してから作成する。計測用の現在サマリであり、過去の試行を次Tの生態入力へ蓄積しない。水分/養分の表示自体は常に確定値で、参照回数と生態の進行を切り離す。

新しい通常図鑑保存はCS07まで拒否する。従来の無指定経路だけを起点と短期比較して旧再生へ接続し、新方式の旧結果互換は登録しない。UI/画像/既定条件・製品4.2.77/配布は維持。
