# CS08三次：共有配分の作業配列

起点90d1e22。current-state/1の同マス内の有限在庫と共有配分を維持する。既存C7.2/C8.2・D7/D8/E5の範囲で、配分の内部表現だけを変更する。

## 内部処理

`CellResources.allocate`は、在庫と要求する栄養の名前を一回の呼出しの初めに番号へ変換する。検証した要求の係数も対応する番号へ写し、残在庫・未充足需要・合計消費率/充足率を数値配列で扱う。

反復ごとのObject/entries作成を避け、消費率/充足率の作業配列を0へ戻して使う。対象となる要求の列も、同じID順を保ってその場で絞る。作業配列や番号はこの配分呼出しだけに属し、世界・保存・Worker転送へ持ち越さない。

次を維持する。

- 有限/非負・重複ID・不正な資源名/需要名の検証。
- ID順、need×ability×reachの重み、加算順、各要求の必要量上限、EPS。
- 独立したE/Mの未充足判定。片方が足りてももう片方を求める混合要求は成立し得る。
- 取り分の切下げ、残量の再計算・丸め、返すgrantsの順序と資源名。
- マスごとの配分、実際の資源移転・支払い・還元・収支。生存数や処理ターンは間引かない。

Object継承名と同名の特殊な診断キーには、従来のオブジェクト方式を残す。通常のゲーム内資源名は番号方式を使う。共有配分の規則や優先順位を新設した変更ではない。
