# CS03：土壌在庫と資源要求の接合

実装契約 `current-state-soil/1`。正本は [current-state/1の5節](../specification/current-state-aggregation-v1.md)、実行範囲は [CS03計画](../../operations/plans/current-state-soil-v1.md)。`src/ecology/soil-matter.js` は既存C7.1/C7.2の補助実装であり、新しいNodeではない。

## 適用と正本

CS02と同じ明示指定 `currentStateModel=current-state/1` の内部比較だけへ接続する。通常フォーム/既定条件、Core、食性・系統の追加、画像/UI配置・製品4.2.77/配布は変更しない。

`cellState.soil` を追加し、旧`cellState.organic`はこの経路では分類付きの分解中在庫へ使う。既存の`tiles[].soilM`が0次養分の唯一正である。`totals`は以下の所有者を各一度数える。BはE内の身体成分であり、別のEとして加算しない。

| 在庫 | 保持単位・所有 | 利用可能時点 |
| --- | --- | --- |
| 新鮮残骸 `soil.fresh` | マス×可食分類×日齢0〜9の量E/M/B | 死亡Tの翌Tから。日齢10で分解中へ移る |
| 分解中 `organic` | マス×可食分類の量E/M/B | 現在の取得処理で共有する。通常の食物同化効率×0.5 |
| 還元待ち `nextMaterial` | マス×有機/無機×必要分類 | 次Tから。生物利用・背景分解の同T再利用は不可 |
| 満杯等の保持待ち `soil.waiting` | マスごとのM現在量 | 次の準備時に土壌の実際の空きだけ受け入れる |
| 寄生/曝露担体 `carcasses` | 現在も有効なP/Q・有限曝露の実ID/期限/所在/在庫参照 | 栄養E/M/B/qは0。実採食または既存の接触経路でのみ作用する |

可食分類は植物、菌、低次動物、主生物動物、その他動物。Q等を低次動物食の対象へ誤分類しない。由来未分類の排出有機物は内部のdetritus区分とし、分解に使えるが、全動物の無条件食物にはしない。これは新しい生物系統ではない。

量機の既存の食性、通常植物の非捕食、光合成体の採食制約を保持する。土壌へ混ざった後に元の死者や源系統を復元せず、観測イベントは在庫分類を明示する。

## 引渡しと時計

1. 死亡時は従来の同T捕獲資格を保持する。確定前の死骸は当該Tの実在栄養の所有者として残し、参加者に限って取得できる。他の主体は新鮮在庫として読めない。
2. 生物利用後/確定前に残量を同マスの新鮮在庫へ一度だけ移す。死者のDNA・外見・全属性は土壌へ複製しない。
3. P/Qまたは有効な死骸曝露がある場合に限り、栄養0の担体を残す。実P/Qの`hostId`、成熟・宿主適合・元の感染期限は維持し、栄養を新しい寄生個体へ変換しない。
4. 新鮮在庫は10個の日齢位置を再使用する。日齢10では分解中へ移し、担体の在庫参照も移す。新しい流入が古い残骸の日齢を若返らせない。
5. 既存背景処理の後に発生した死亡も、最終確定時に同じ引渡しを通す。背景分解はそのTに新しく生じた残骸へ遡って実行しない。

## 取得・分解・端数

主体×同マスの在庫区分で要求し、既存の同時配分器で分ける。分解者の身体/処理能力、水、E/M要求、各主体の保持上限を共有制約とし、死骸の数だけ処理能力を増やさない。要求順で量が変わらないことを確認する。

取得されたE/M/Bは同じ一つの在庫から減らす。未同化分は分類を保持した次T有機物または無機養分へ渡す。分解中在庫の食物同化は0.5倍、菌の分解によるE同化は従来の0.5を維持し、二重に0.5を掛けない。

背景分解は既存の気温/pH/水分/土壌活動係数から `min(1,0.02×活動係数)` を求める。正の率がある微量成分は最小0.000001まで処理し、最後のEは熱、Mは次T還元へ渡す。乾燥等で率0なら有機物を残せる。E/BがなくMのみとなった在庫は保持待ちへ移す。満杯Mを死骸IDの栄養として残さない。

在庫に5成分の現在の栄養構成を受け入れる欄を用意する。CS04の摂取構成接続前は、植物由来と不明を区別し、非植物の未観測の段階を勝手に補完しない。取得/分解/合算ではEに応じて現在量を比例移転する。これは分子/粒子追跡や死者の履歴保持ではない。

## 寄生と観測の境界

在庫の実採食時に、その在庫へ付随する有効な担体だけを参照する。有限曝露は実際の採食割合だけ移転し、成熟Pの移行確率も混合在庫の採食割合を通す。成功したP/Qは既存の移行待ちへ一度だけ移す。繁殖・感染適合・Qの感染窓や羽化条件は変更しない。

移動時の餌評価・自律Qの探索も現在の在庫を参照する。場所/主体ごとの索引を使い、採食のたびに全死骸/全担体を再探索しない。

内部の `soilMatterSummary` は在庫区分数・E/M/B・保持待ちM・感染担体数を示す。残骸の区分数を死亡個体数へ読み替えない。採食イベントに源分類と現在の栄養構成を渡し、CS04/07へ接続する。全Tグラフ/画面/新しい保存形式の完成を意味しない。CS02の新状態保存拒否は維持する。

従来方式は変更していない経路を起点比較し、`currentStateModel` 未指定だけを旧署名の再生へ接続する。新しい集約規則の旧結果互換は登録しない。
