# マス再編：実装の意味・責務・接合契約

管理版 `cell-implementation/1`。上位正本は [cell-reorganization/1](../specification/cell-reorganization-v1.md)。既存C7系/C8系・D7〜D9へ接続。CR06の水域専用比較プロファイルと下層生活を内部接合。新境界12＋資源20/分解循環21/基盤8の計61項目を限定確認。淡水光合成体の専用生活・CR06全体・通常観察は未完。 淡水光合成体の専用生活、群落移動の種指定/再生枝、観測/設定/表示/保存開放とCR07代表長期は残件。 正式構造・製品版を維持。現在の証跡は [CR06水域資源接続](../../operations/evidence/cell-aquatic-resources-v1/README.md)。

## 1. 版と適用境界

新方式の設定入口を `config.cellModel: "cell-reorganization/1"` とする実装案を採用する。これは実装上の版識別で、利用者向けに内部設定を増やすUI指示ではない。未指定の旧世界を新方式へ自動変換しない。新方式の必要状態を持たない旧署名へ、新しい収支・枠を名乗らせない。

採用済みのA/B数値と構造を参照し、Cで系統・枝・能力・枠を追加しない。マス再編以外のP/Q生活環、情報の役割分類、造形、表示方式、記録対象選別、速度切替の意味を維持する。新方式の既定化は、結合と保存・画面接続が通った後の工程とし、途中版を完成版として配布しない。

旧版の再生互換は、実際に旧経路が同じ結果を出す条件に限定して署名へ接続する。新しい署名を単に旧署名へ登録して一致とみなさない。現行製品4.2.77の記録・資料は、その対象版の根拠として残す。

## 3. 共通状態と所有権

### 3.1 固定と動的な状態

- 固定側：地形・通行情報、雨/光/気温/pH/土壌の質、実効保持量、系統/相の基礎係数。世界作成時に解決・保存し、参照キャッシュを共有する。
- 動的側：利用可能な水分・無機養分、各実有機物、群落の基部/可食部/蓄え、内部世代、定住/移動、量機の定住枠参照、腐敗負荷、次T利用待ちの物質。
- 資源の正本は一つにする。現行 `tile.soilM` と新在庫を二つの書込可能な正本として併存させない。新旧経路の読取アダプタと、収支を動かす唯一の書込口を分ける。
- 層別の参照索引は派生データ。個体の所在や資源台帳と独立に生物を所有しない。移動・出生・死亡の確定後に該当マスを更新し、旧代表1体Mapだけを正として使わない。
- 全個体の全履歴や、内部8体それぞれのAIを追加しない。内部世代の整数人数と実物質を保存する。

現行Worker差分には `soilM` の専用転送が既にある。これを無視して全面再送へ戻さず、新しい水分・腐敗負荷・利用待ち等を適切な差分へ接続する。固定地形キャッシュに動的在庫を固定してしまわない。

### 3.2 占有の表現

マス→空間層→実ID列を取得できる共通入口をC7.1が所有する。主生物には移動/定住の区別と、量機の相変異型だけの定住枠内所属を持たせる。定住枠内のまとまりは空間の参照であり、栄養・寄生・繁殖をまとめる新群体ではない。

必要な状態・判定は、固定枠、使用枠、空き希望、合法な進入、定住希望、解除待ち。枠数と実個体数を別に返す。生存・死骸・情報・感染体を同じ占有列に混ぜない。

下層1次6群、2次3体、3次5群、5次6群を別に保持し、同種でも複数の群落/群が存在できる。淡水光合成体は4次だが、生産者属性や光合成の処理を失わない。`slot` や `group` の文字列を単に `main` へ変更して肉食・主生物維持費等を誤適用しない。

### 3.3 初期配置と整合性

新モデル用の明示値・0・合法な適地を尊重して配置する。容量拡大だけで初期群落数を6倍にしない。初期のE/M/身体を台帳へ計上し、設定値と実配置の理由を保存する。新規世界だけの混合年齢等と、子のI相/年齢0を混同しない。

初期配置完了時点の定住参照を確定する。量機の初期状態も実際の通常/相変異に従い、9体を許すために通常型へ相変異を自動付与しない。初期時点から全枠最大数を置く方式に変更しない。

## 4. 資源要求・予算・収支

### 4.1 要求と配分

要求は実主体ID・所在マス・実資源ID/種類・必要上限・取得能力・届きやすさを持ち、配分と実移転を別段階にする。候補リストの先頭で恒常的に有利にならないよう、ID安定の抽選キーと、順序を変えても意味が変わらない上限付き重み配分を使う。

光は受光/遮光と実際の光合成利用を分け、同マスに一予算だけを置く。水・養分の組合せが満たせない要求は、実利用量へ制限する。到達性は同マス内の係数として扱い、別マスの内部資源取得や層番号だけの優先へ変えない。

食物要求は実在庫を共有し、同化率と原料引落しを分離する。捕食者・菌食者・分解者ごとに別の複製在庫を作らない。部分損失では実消費量・実死亡量・食べ残しを分ける。

### 4.2 予算

実行済み費用→維持→維持3T分の留保→任意投資→余剰貯蔵の順を共通契約とする。留保は費用ではない。成長・修復・再生・出生が同じE/Mを二重予約しないよう、予約済み量と支払済み量を参照する。取得予定を確定済み資源として前借りしない。失敗予約は費用を発生させず解放する。

形成に使った養分は組織、未無機化分は有機物、無機化分は0次、E散逸は熱という行き先を一度だけ確定する。現行 `addSoil` の上限超過を `Mloss` へ落とす処理は、新モデルでは保持待ちに置換する。有限環境での合法な排水と、養分の黙った消去を混同しない。

### 4.3 利用待ち

新生・新葉/組織・還元・死骸/排出物・情報・新資格の境界は上位10節を使う。次T用物質は利用可能Tを明示し、末尾状態と保存・転送へ含める。次Tへ渡した後は一回だけ利用側へ移す。無制限履歴ではなく、必要な未反映物質だけを保持する。

直接捕食した部分は当Tの受取側へ移せる。死亡残骸を同じ部分から重ねて生成しない。死骸の感染性の期限は栄養量の消失条件ではなく、残存有機物の分解と別に処理する。

## 5. 行動・生活・寄生への接合

各歩での候補、収容枠、実費、交戦停止をC7.3で扱う。定住と移動の枠参照は共通入口へ集約し、経路探索・実移動・出生・解除のそれぞれに別の容量式を埋め込まない。満員・通行不能・予算不足・交戦不成立の理由を区別する。

生活処理はC7.2/C7.4が共同で担当する。植物の基部/可食部、分解者の基部保護、低次動物の内部人数・部分死亡、出生費、分群7〜8から3、自動合流なしを上位表へ接続する。衰退値を増やすだけで予算不足を隠さない。群落の成立後Tを個体寿命にせず、個体の年齢成熟は相と独立に進める。

P/QはC7.5の実ID所有を維持する。圧縮量機9体を1宿主へまとめたり、分群で同じP/Qを複製したりしない。途中接触、死亡・直接捕食・新死骸を既存経路へ一度だけ接続する。今回のマス再編だけで感染窓・卵数・生活環・情報の栄養性を変更しない。

背景分解は生物処理後の残量から処理し、菌の直接負補正なし・軽い腐敗負荷の上限を守る。未決の曲線・水中専用値等は実装比較値として一覧化する。上位の意味・上限を変える場合に利用者へ確認する。

### 5.1 CR06消費者の内部境界

- `CellResources.lifeDemands/acquire` が主生物・低次動物・自律Qの所在マスの実食物をまとめて配分する。E/Mの片方だけが満量なら、他方に有用な要求は止めない。実在庫・合計採食量は共有し、余剰E/Mは次Tの有機物へ渡す。菌の処理損失Eは既存の熱、未保持Mは次T無機化へ分ける。
- 身体はB、身体結合Mは `cellMatter.bodyM`、自由Mは `o.M`。主生物の初期身体MはB×0.02を初期台帳に一度だけ含める。既存の物理資源（非情報/非変異因子）はq単位、非生物有機物は実BまたはE・M/0.02の身体換算を採食枠へ接続する。派生資源キーとマス別索引を使い、原在庫を複製しない。
- 維持費の要求と実支払を同じ小数6桁へ揃え、丸め端数を栄養不足や全投資禁止にしない。主生物の維持不足は既存の未払E×2のHP損失。有償回復は既存の年齢/系統/枝によるE→HP同化率を使い、実維持3T留保を使い込まない。既存の学習/進化、年齢進行と寿命死亡へ接続する。
- 主生物は全食性共通の定住枠を使い、同マスも出生候補。既存の成熟・雌雄・単為生殖・貯精/交配・量機条件を保持し、旧近傍2/3体や密度直接罰を再導入しない。相変化で得た新資格を当Tの出生条件へ前倒しせず、子はI/年齢0、通常量機として独立枠を持つ。
- `CellMain` の出生は既存の子E/B/Mと基礎費用を使い、総費用が `子E＋1.2×子B` / `子M＋0.02×子B` に不足する場合だけ形成不足分を加算する。比較用接合式として、既存E拠出比で追加費用を各親へ配る。両親を先に予約し、全員成功してから一度だけ引き落とす。失敗0、親一回、既存余剰Mは次T還元。遺伝変異幅/子の栄養/出生数/枝を新たに増やさない。
- 自律Qは既存の維持・有限分割・局所探索・有償移動/産卵を保持し、移動先の共有採食へ参加する。原料Eで既存採食上限を測り、既存同化率/保持E上限、Mを保持しない点を使う。情報は栄養にしない。当T羽化/新生Q、新葉、新死骸を即時の追加資源にしない。
- 淡水光合成体の専用生活などは次の境界。旧遠隔採食や当T死骸の即食を代用品として有効にしない。通常ターン/新図鑑保存の公開ガードを維持し、内部接続を完成ゲーム/長期存続認定へ拡大しない。

### 5.2 同マスの直接捕食

- 実際に成立した攻撃参加者は `cellCombatSources` に保持し、描画イベントから生態判断を逆算しない。攻撃側も死亡した場合や遠隔のままの場合には、当Tの取得資格を与えない。
- 同マスの全小集団と開始時に自立していたQを、既存の食性/局所食料評価へ接続する。通常食料も比較し、比較実装では一捕食者が一度の捕獲で実在1個体を抽出する。不要な捕獲、同族主生物の捕食、新生Qへの即食、寄生中Qの直接被食を追加しない。QはMを持たず、M不足だけでは捕獲しない。群落/個体の全盤探索を各捕食者へ増やさず、マス別索引と既存形質を使う。
- 撃破者/捕獲者の当T取得は `capture` 資格で区別する。物理的なE/M/Bは死骸/食べ残しの一行で所有し、資格はその在庫への限定参照とする。一般の `carcass` 取得は新死骸をT+1まで拒否したまま。食物配分・合計採食上限・保持上限は既存の共通取引を使い、別在庫や同一部分の二重受取を作らない。残りの利用可能TはT+1を保持する。
- 小集団からは整数人数と実コホートB/自由E/M/身体Mを抜く。戦闘死で消失した人数のHP単位と、残存個体の負傷を分離し、負傷を人数比で軽減してさらに差し引く処理を避ける。残存人数へ保持上限/維持を接続。幼体群も新版のHP上限を使い、旧版の年齢上限による追加損失を混ぜない。飢餓の部分死亡にも同じ残存負傷を適用する。
- 実消費割合でPの `feeding` 経路を試す。既存の成熟/適合/遺伝/抵抗と次T定着を維持し、同じ捕獲を死骸経路でも試さない。残るP/Qは一つの実保持者または移行先に属する。
- 自立Qは既存の回避率/費用を使う。一回の成功はそのTに有効で、別の捕食者が重ねて費用を請求しない。捕食成立時はQの実E/Bを同じ物質在庫へ移し、死亡処理で二度散逸させない。Qの維持/発育/感染窓/羽化率は変更しない。

### 5.3 植物共生体の共有光

- `kelp` は主生物のまま、最終所在マスで植物と同じ光予算・水分を共有する。基礎光1.5×既存相係数×年齢の光係数×所在光量を受光上限とする。固有樹冠係数が未選定のため、比較接続は既存面積1/高さ優位なしの基底帯0。造形から専用の高さや生産ボーナスを推定しない。受光と利用を区別し、水1/光E2.6・温度/pHを実受光の利用上限へ接続する。
- 光の単独E要求と採食のE/M要求は同じE不足を満たす。純Eである配分済み光を先に実移転し、Mのために必要な採食は継続できるようにする。M目的の食物の余剰Eは次T物質へ渡し、配分済み光を後から容量超過で廃棄して水だけ失う順序にしない。
- 植物共生体は光合成＋小型動物食。候補・自動要求・直接要求で植物/菌の採食を拒否する。新しい土壌M吸収は追加せず、既存の動物食/鉱物の有限取得を使う。通常植物の非捕食と、他の主生物の食性・維持/繁殖表を変更しない。
- 実光Eはイベント/当T記録へ一度だけ記録する。既存のE≥60/M≥1でE1→G1、当T旧相/年齢の資格を維持。新生体の当T光合成、相進化による無料補充は行わない。光合成の温度/pHを主生物の採食効率や維持へ一律に適用しない。

### 5.4 明示版の水域プロファイル

- 正本13.3節の実装比較として、`cellSettings.aquaticProfile: freshwater-comparison/1` を明示した場合だけ有限な水域を解決する。水分上限40/初期32、局所入力8×雨倍率、20℃の基準蒸発0.5。底質Mの乏しい4/16・標準8/32・豊か16/64（初期/上限）、上限へ共通土壌の質を適用する。水域の水量を土壌保水量へ置換しない。理由と規模比較は `operations/plans/cell-aquatic-resources-v1.md` に保持する。
- 水域の境界入力を `waterInput`、降雨入力を `rain` として固定状態で区別する。明示版水域のrainは0で、二重に加算しない。更新は前在庫＋入力−排水−実蒸発−実利用、一回だけ。底質Mは唯一の `tile.soilM`、外部M入力は明示設定のみで標準0。光予算/株数/採食量を見て生体や栄養を補填しない。
- 未指定の水域は未解決状態を維持し、陸の値や新しい比較値を黙って代入しない。未知の版や設定/固定状態の不一致を拒否する。既存の陸プロファイル、気温/pHの生物別応答、同マスのみの取得と次T還元・余剰保持を維持する。
- 微藻/水生植物・水游虫小集団・分解者の有限生活を接続。自然な長期循環の認定ではなく、実在食物・置いた旧死骸・短期の還元を確認する。動く淡水光合成体の生活は別の残件。`group/slot` をmainへ変えたり、定着高次植物の数値を流用したりして未接続を隠さない。

## 6. 観測・描画・保存

各実装単位で最低限の観測投影を同時に接続する。C8/C8.1は、複数層/複数実ID、量機の人数、小集団の人数と群数、群落の基部/可食部、移動/定住を既存の詳細・追跡・記号へ渡す。新しい絵柄・層分離・画面配置をこの工程の都合で追加しない。
