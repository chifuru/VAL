# CS07前半：Workerとネイティブ記録の接合

対象 `current-state-integration/1`。起点34b6f57。上位は [current-state/1](../specification/current-state-aggregation-v1.md) 9節。既存C7/C7.1/C8/C8.2、D7/D9内で接合する。新Node・正式状態変更はない。**工程7の前半であり、通常画面/グラフ/個体詳細/CSVの全接合は未完。**

## Workerの現在状態

従来の場所情報は由来IDで識別する。新しい場所情報はそのIDを持たないため、マス・適用範囲・役割・源系統/相手系統・意味・確度・正負・期限の組で識別する。同マスの別内容を一行へ上書きせず、更新・消失・並び替えを反映する。

新方式の `cellState` / `currentInfections` / `currentActivity` は、オブジェクトの変更/削除キーと、長さが同じ数値配列の変更位置を転送する。未変更の固定設定・地形・マス環境定義を毎フレーム送らない。変更しない配列を複製せずに受信世界へ引き継ぎ、送信元・前フレーム・既に送ったパケットを変更しない。

段階表示時にも必要な現在状態の差分を渡し、一括・段階送信・最終のみの3経路で確定世界を復元できるようにする。過去観測の全期間をWorkerの世界へ入れない。途中表示と確定を混同せず、取消では確定世界の現在時計/更新候補を保持する。

実Worker照合では、追加系統の既知リストが新規作成時にだけ初期化され、再開先で相手が不明になる問題を検出した。CurrentInformationは実経験を記録する際にも、現在の実効設定から必要な系統を登録する。世界の再初期化・経験の消去・本人実績の捏造は行わない。従来の無指定経路は変更しない。

## 新しい記録形式4

`current-archive.js` が `schema:4` を扱う。従来1〜3を上書き/黙って変換しない。新形式は `current-state/1` のネイティブ `current-observation-snapshot/1` を要求し、旧グラフの形式へ偽装しない。

- 実効初期条件、署名、最終ターン・結果指紋、最終集計/台帳、観測側の世代集計、全Tの集計行を保存する。
- 最終のマス内実在庫/環境定義、感染量/遺伝型参照、更新候補/現在時計、局所情報と現在の情報台帳を保持する。
- 生物/P/Qは各4例までの現在状態を保持し、総数と省略を明示する。実ID・直接参照・初期値＋a・現在の発信/受信・摂取構成を含め、過去の世界を毎T保存しない。代表例から個体全体を復元した扱いにしない。
- 一覧は短いヘッダだけを保持し、全T行や最終状態を二重に一覧へ複製しない。本文読込時にヘッダとの一致を検査する。

保存前に確定状態の不変条件、全T/条件/署名/最終集計・物質収支・現在量/型参照・代表例の形式を検査する。本文の整合ハッシュも照合する。未確定な段階表示や欠測行を記録へ混ぜない。ハッシュは破損検出であり、外部者による正当性保証ではない。

読取は保存データを検証するだけで生態を進めない。同じデータ形式で署名だけが異なる記録は結果を読めるが、対応しない署名からの再計算は拒否する。再計算する場合は必ず実効初期条件から行い、最終の代表例/在庫から途中再開しない。再生だけでは書き込まず、再保存は明示した `replay-new` と新IDで行う。

新方式の新規記録はこの形式4/APIだけへ接続する。旧CellArchiveの形式3に対する新状態保存拒否は維持する。通常画面が新形式を生成/読取する接続は後半で行い、既定モードをこの前半で切り替えない。
