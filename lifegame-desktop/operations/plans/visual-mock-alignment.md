# モックへの外観接続：実行契約

利用者の「モックに近い見た目で作っていって」を受領。project-local Operationを先行読込し、Summary/Flow、現行Manifest、B5/B5.3、C8/C8.1、D9、E6/E7と実画像を照合した。既存の描画・観測責務で吸収できるため、新規Nodeや分割は行わない。前提フィードバックは接続可。FLOW-04→05→08で外観修正・反映・実測記録を行う。

基準はdesign/specification/ecosystem-overview-mock.png、habitat-overview-mock.png、design/visual-mocks/ab-habitat-food-four-phases.png。初期の実行モックdesign/ecosystem-mockで使った生物画像の造形も参照する。旧画像に含まれる数字/FizzBuzz、旧環境数/栄養/繁殖条件は採用しない。現行の30系統、8固定環境、有限収支、局所9重み、寄生H→P→Q、出生/相/枝/雌雄/階級を保つ。

変更はC8のレイアウト・肖像/説明表示、C8.1の生物画像と地形/餌/確定演出、D9の画面/画像読込/観測独立検査、配布版/証跡へ接続する既存C4/D4/E6/E7に限定。生態src/ecologyのhash/catalogue/state/nutrition/behavior/reproduction/parasites/engineは変更しない。A/Bの新しい生態ルール・承認状態・core・添付原文・他プロジェクトを変更しない。

生物は既存モックと同じ素材生成元から四相の描画用アトラスへ書き出し、現行状態で相を選ぶ。外観テンプレートの部位成長値は描画の製造時だけ使い、実行時の生態へ逆輸入しない。原素材を他プロジェクトから変更せず読み取り、配布に必要な描画資産を本プロジェクトsrc/assetsへ内包する。背景は固定環境/地形に沿うテクスチャと障害物をキャッシュし、UI付きモック画像を盤面へ貼らない。

検証計画は画像読込/相・系統の描き分け、実体に一致する地形/選択/肖像/雌雄/寄生、拡大縮小・描画・画像準備前後の生態指紋不変、狭い表示、各操作/説明、外部通信/例外、Windows ZIPに全資産を含め実exeが進むこと。実画面PNGと対象ソース/資産SHA256をE6/E7へ記録し、未検査の外観を検証済み扱いしない。生態E5は変更しない対象ファイルの同一性を確認して有効範囲を維持する。

完了条件は、実画面をモックと視覚照合し、上記検査と配布検査を通し、Manifestに現在の状態・証跡・残る認識合わせだけを反映し、mainへpushしてクリーンにすること。ユーザーの主観的な外観承認は代行せず、結果を提示する。新しい責務分割や生態ルール変更が必要になった場合は停止して確認する。報告はVALIS/READ/TASK/INPUT/NEXTを守り、Operationの作業結果照合・出力前ゲートを通す。
