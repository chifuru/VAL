# 実装の12作業単位と進行条件

計画版 `implementation-sequence/1`。基準main `58509f1`、製品4.2.32。利用者の実装着手指示に基づき、今回はまず作業の切り分け・順序・範囲・確認条件を確定する。仕様は[現在のA/B](../../design/specification/README.md)、最適化候補は[41件の調査](optimization-before-implementation-v1.md)、全体の対象範囲は[現在ロードマップ](completion-roadmap-v1.md)を参照する。

## 計画と実行契約の区分

本書はFLOW-12で分離した実装順の計画。個別の実装/検査/Node/Manifest更新は各単位の実行契約を正とする。I01には[共通基盤の実行契約](i01-runtime-foundation-v1.md)を適用し、既存C/D/EとManifestを同じ単位で更新する。計画の作成だけを実装完了とせず、各単位の実測範囲を分ける。

以下のI01〜I12は**実装の作業単位**であり、12個の新Nodeを作る指定ではない。既存C7/C7.1〜C7.5、C8/C8.1/C8.2、C4と、D7/D8/D8.1/D8.2/D9/D4の責務を利用する。着手時に関連本文を実読し、必要なC/D更新・検査・E証跡・Manifest反映を同じ単位へ含める。責務/変更単位/検証観点から新Node分割が必要になった場合だけ、具体案を先に提示する。

A/Bの仕様議論は一旦区切り済み。未選定係数は提示済み[実装開始案](../../design/implementation-start-v1/README.md)を版付きの比較値として使い、数値調整を毎回利用者へ戻さない。個別採用された条件と比較値は区別し、未実測値を最適値/実測合格にしない。系統・枝・能力の意味・可逆性・個体単位等の変更が必要な場合だけ設計判断へ戻す。

I01〜I09に続き、I10「描画・素材・行動表示」を開発版4.2.42へ接続した。[実行契約](i10-rendering-materials-v1.md)と[限定検証](../evidence/i10-rendering-materials-v1/README.md)が今回の対象。P18形態/Q4相の採用透過素材、予熱/旧経路、確定マークの一回受領と同seed新世界、既存の植物/量機/21主系統・同居選択/背景保持を扱う。現行画面構成を維持し、追加の構成修正は実稼働後へ回す。次はI11生存・創発・性能調整。P/Q自然長期循環/500T/R1〜R6は未認定、新WindowsI12も未完。配布済み版は4.2.32。

## 各単位に必ず含めること

1. **読解と対応付け**：関連core・A/B正本・既存C/Dを実読し、処理順/保存版/影響範囲と必要なNode更新を決める。既存最適化を二重実装せず、更新する生成元と生成物を揃える。
2. **実装と最小限の観察接続**：計算だけで終えず、盤面/横詳細/計数へ現在状態を渡す。新状態のWorker転送・保存/復元・定義版も同じ単位で扱う。I08〜I10はこの接続の初着手ではなく、条件生成/画面全体/品質を完成させる段階。
3. **必要な確認と証跡**：境界/収支/ID/再現性と、その単位で変更した表示・操作・保存を確認する。最適化だけの差には旧結果一致、新しい生態には新規則の成立を要求する。出ていない機能の合格まで認定しない。
4. **記録と統合**：C/D/E・Manifestの必要差分と実測範囲を揃え、途中の未達を残してmainへ統合する。Nodeの草案状態と、実装/検査成功は区別する。作業用ブランチを使う場合も単位完了後は統合・整理する。未接続の途中版を完成版として配布しない。

## 最適化41候補の組み込み方

- **I01**：共通索引・所有権・生成経路・変更記録の入口を整える。全面dirty化/保存形式刷新/GPU化を全部先に終える工程にはしない。
- **I02〜I07**：機能の改修箇所で、重複検索・不要候補・近傍集計・有限窓をまとめて改善する。廃止する旧Q処理だけの最適化には投資しない。情報/寄生/群落の記録を後から全走査で回収する構造を避ける。
- **I08〜I10**：Worker解放、保存/解析のコピー、出力一本化、描画索引・可視候補、近景背景保持、画像キャッシュ在否、描画予約/必要DOM更新を接続する。
- **I11**：測った箇所に対して追加のWorker加工/アトラス/部分再描画/列形式通信/逐次保存等を選ぶ。不要な全41件実装を完成条件にせず、見送り理由を残す。全ターン原値や生態/造形を削って速度を作らない。

## 進行順と確認のまとめ方

基本の順は **I01→I02→I03→I04→I05→I06→I07→I08→I09→I10→I11→I12**。

ただし、これは変更を主に確定する順序であり、無関係な作業を待たせる指定ではない。量機I04は共通基盤/生産基盤があれば着手可能。既存UIの停止/不要欄整理、採用素材の準備、観測/保存の器は生態の完成前に進められる。関係面やQ情報作用など新状態の意味に依存する箇所は、該当状態が揃ってから接合する。

確認は、各単位の必要な短期検査→まとまった生態の比較→画面/ビジュアル確認→細かなバランス/性能→総合確認の順。毎係数変更で500T・全画面・Windows配布を繰り返さない。生存を支える基本循環は前半で確認し、最終の細かな調整はUI/ビジュアルを見てから行う。R1〜R6は最終完成判断として維持する。

次の着手点はI11。I10の接続/限定検査は `operations/evidence/i10-rendering-materials-v1/README.md` を参照。既存責務を超えるNode分割・未採用の意味変更・大きな造形変更が必要になった場合だけ、対象と案を具体化して確認する。
