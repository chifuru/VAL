# 第4工程・記録容量の整合

基点main 648bdd0。FLOW04→05→08、既存B5.5/C8.2/D9/E6内。新Node/分割/正式状態変更なし。中断中の速度案は含めない。

1. 小さな高密度詳細fixtureで、解放前の容量判定が停止する反例を記録する。
2. 解放計画を判定へ含め、失敗時は確定行を不変にする。
3. 読込上限を拡張可能記録量へ整合し、行ごとの容量/非有限値検査へ置き換える。
4. 反例/原値一致/境界拒否/拡張後再試行/行単位読込を限定確認し、既存の観測と図鑑検査だけを再実行する。
5. 必要なら実Workerの容量故障注入で確定ターン保持・再開を確認する。生存試験/全件回帰/Windows/配布はしない。
