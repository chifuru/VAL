# CR03：有限資源・配分・栄養予算

上位は `design/specification/cell-reorganization-v1.md` 3/4/10節、C/D契約は `design/implementation/cell-reorganization-v1.md`。継続指示をCR03へ接続する。

- FLOW-04/05の実装差分、FLOW-07/08の限定確認・証跡。C7/C7.1/C7.2/C8.2、D7/E5の既存責務内とし、新規Node・分割・初期登録は行わない。
- 固定の環境適性と動的在庫を分ける。有限の水・無機養分・光・食物要求を同マスの実IDへ結び、上限付き重み配分・余りの再配分・複数資源の成立量で確定する。
- 共有光は高さ別に捕捉し、捕捉量と実際の光合成を分ける。未利用光はそのTで失われる。CO2は十分に供給される前提で個別在庫を作らない。
- 実行費→維持→維持3T分の留保→任意投資の順。予約・取消・支払を分離し、同じ栄養を重ねて使わない。身体の養分と自由な蓄えを区別する。
- 排出/還元待ちを次Tへ渡し、上限を超えた養分を有機物側へ保持する。soilMを唯一の無機在庫とし、E/M保存・合法な外部入力・熱散逸を区別する。
- 下層の自動要求・初期身体/生活/繁殖/分解の全体接続はCR04/05。CR03は実主体・実在庫を扱う内部APIと段階入口まで。新方式の通常進行・図鑑保存ガードを維持する。
- 水系の供給/底質係数は未選定のまま保持し、陸の数値をコピーしない。専用値が必要な内部処理は未解決として拒否する。陸の温度依存蒸発曲線等の比較開始式は証跡に明記する。
- 少数確認：不足/余剰/上限/順序入替、複合資源、隣接取得0、共有光/遮光、固定環境適性、実食物共有、費用/予約/取消/形成、次T一度だけ反映、保持上限とE/M保存、Worker/生成/旧短期一致。
- 不変：3core、A/B意味・採用数値、正式状態/階層/参照、UI・画像、能力値バランス、製品版・配布。500T・全件・画面・Windows検査は行わない。
- 完了：実装・限定証跡・担当C/D/E・Manifestの現在要約を照合しmainへ統合。次はCR04。
- 上位意味・枠・数値の変更や責務分割が必要な場合は、その部分を推測で進めず確認する。
