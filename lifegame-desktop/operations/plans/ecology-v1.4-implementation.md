## 実行契約

FLOW-04。目的は現行A/Bに従うゲーム実装。前提はproject-local Operation先行制御、Summary/Flowの構造・実行契約・ゲート。実装の許可は受領済み、Node分割の確認後に接続する。

作るものは上記C/Dと実装/tests、実測に対応するE・operations/evidence。更新は既存実行構成・該当Node・README・Project Summary Manifest。coreと添付原文、他プロジェクト、承認状態は変更しない。新NodeはManifestへ初期登録し、成果/証跡に応じて反映する。

順序は共通世界/予算→採食/移動/戦闘→相/出生→P/Q/情報→画面/説明/演出→配布接続。段階ごとに意味のある検査を実行し、最後に結合・描画独立性・初期値別の進行/負荷を確認する。未実施環境を合格と報告しない。

完了条件は現行範囲を実装し、必要な検査・証跡・Manifestと実体を照合、main統合、清潔な作業ツリー。停止条件は新たな分割変更が必要、利用者の意図が変わる仕様対立、利用できない環境に依存する検査。ブロックされない作業は継続する。

出力前ゲートで実読/実装/実測/Manifest/未確認環境/次作業を照合し、VALIS / READ / TASK / INPUT / NEXT形式で報告する。
