# I11b 下層・寄生の生存経路に対する実行契約

基準main `1b248aa` / 開発版4.2.43。project-local Operation→Summary→Flowの関連制御を実読し、第零次前提・Identity Kernel・前提フィードバックを有効にする。主FLOW-05、実測記録FLOW-08。利用者の継続指示と、I11初回で残した下層/寄生/性能の課題へ接続する。

## 範囲と責務

既存C7/C7.1〜C7.5、C8/C8.1/C8.2、D7/D8/D8.1/D8.2/D9、E5/E6を利用する。61Nodeの正式状態/階層/層間参照は保持し、新Node/分割/初期登録はしない。採用済みA/B、core、UI構成・遠景記号・近景造形・画像を変更しない。正式状態変更や新しい責務/生物/生活環が必要なら具体案までで止めて確認する。既存責務内の係数選定・不具合修正は委任済みのため自律的に比較する。

1. 草棲虫は捕食損失と局所回避、栄養の回復/出生費・成熟/待機/空き場所を分離する。菌膜は実在の有機物・材料・定着機会と採食損失を分ける。無親生成、群落化、寿命だけの延長で維持を作らない。
2. Pは初期宿主→放出/有限量の曝露蓄積→侵入/定着→次宿主/再放出、Qは合法な実初期数→限定窓→定着/発育→有償P致死羽化→同Q IVの採食/産卵→子の定着を分ける。未配置と配置後消失を区別する。窓延長・宿主透視・娘PへのQ継承・救済補充を追加しない。
3. 前回の近景準備/保持メモリは独立に読取監査する。生態の比較を優先し、画質低下や表示の省略で改善を作らない。新しい描画改修は必要性/効果が確認できた範囲だけ別途接続する。

## 比較と変更の管理

- まず実装と同じ製品計算で50T以下の局所/短期診断を行う。設定・source SHA・実初期配置・失敗/支出・ID/親子/時刻を保持する。構成したfixtureの成立を自然長期循環へ一般化しない。
- 旧規則の無変更一致を確認し、候補は原因単位で比較する。有望な候補だけ固定3条件500T、担当群の固定10条件と別の未使用3条件へ進める。既観測のseedを未使用条件として再利用しない。今回の有限な検証範囲と全22系統/R1〜R6の未評価を分離する。
- 生態の意味が変わる採用候補は `balanceModel: survival/2` で分離し、survival/1および版なし記録の挙動・全実効値を維持する。保存/再生・生成8経路・Worker/全確定T観測を同じ署名へ対応させる。source freeze後の結果だけを採用版の根拠にする。
- 実測結果は `operations/evidence/i11b-foodweb-routes-v1/` へ記録し、前回の対象版付き証跡を上書きしない。全Tの集計原値を保持し、毎Tの全世界保存は行わない。比較runnerの不一致/設定不備/失敗を隠さず、生存率の分母を成功例へ選び直さない。
- R1〜R6の閾値は維持する。P/Qが存在することや探索Qだけの残存を生活環成立としない。新Windows/ZIPと最終配布はI12。

## 検査・反映・出力

関連C/Dへ本契約を先に接続してからsrc/testsへ進む。境界・有限会計・死因・出生/次世代・寄生の窓/同ID・再現性・新旧記録・生成経路を変更範囲に応じて検査する。計算変更だけで毎回500Tの実画面を繰り返さず、Worker/保存の短い実画面と直接計算の同条件照合を用いる。過去版の速度を新しい版の達成へ転用しない。

実結果と対象署名をE5/E6へ接続し、Node/Manifest/実体・core/A/B/採用画像不変を照合し、出力前ゲート後にmainへ統合する。今回の完了は採用した差分と限定検証の完了であり、未達のR/下層/寄生/性能を隠さない。報告はVALIS / READ / TASK / INPUT / NEXT。READは実読、INPUTは利用者に必要な入力だけ。
