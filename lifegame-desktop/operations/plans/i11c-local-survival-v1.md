# I11c 局所の生存・寄生収支に対する実行契約

基準main `48876e7`、開発版4.2.44。project-local Operationを先に読み、Summary/Flow、関連A/B/C/D/EとI11b実測へ接続する。第零次前提・Identity Kernel・前提フィードバックを有効とし、主FLOW-05、実測記録FLOW-08を使用する。利用者の継続指示と既存の係数選定の委任を根拠に、前回の未達へ続ける。

## 範囲と前提

既存C7/C7.1〜C7.5、C8/C8.2、D7/D8/D8.1/D8.2/D9、E5/E6の15責務を利用する。全61Nodeの正式状態・階層・層間参照を保持し、新Node/分割/初期登録はしない。A/B・core・R1〜R6、系統/生活環、採用画像、画面構成・遠近表現は変更しない。既存責務内の不具合と有限な係数を比較し、意味や責務の追加が必要な場合だけ具体案を示して確認する。

草棲虫/菌膜は、実摂取・出生/材料/成熟・被食/戦闘を区別する。P/Qは、初期不在と配置後除去、P成熟/次宿主、実際の限定窓とQ接触、維持/発育/放出/羽化の実費、同Qの自立/子の定着を区別する。任意支出が維持を奪う場合と、宿主除去/捕食による失敗を混同しない。

## 実行と検証

1. 読取診断は固定された旧条件の50〜60T以内から開始する。実装と同じ製品計算を使い、監視が状態を変えないこと、源コード/実効設定/実初期数・失敗理由を保持する。既存の全T証跡を再利用し、巨大なJSONや原コードを複製しない。
2. C/Dへ本契約を先に接続してからsrc/testsを更新する。根拠のある最小候補を選び、有限E/B/M・実費・待機/密度・適合/抵抗/成熟窓・同IDを維持する。無親補充、新しい栄養源、寿命だけの延長、窓延長/再発行、娘PへのQ継承や宿主の透視は加えない。
3. 生態が変わる差分は `balanceModel: survival/3` へ分離する。新しい既定値は実効設定へ保存し、利用者が指定した値/0を尊重する。survival/2・survival/1・版なしは従来の計算/設定を保持する。生成8経路・署名・保存/再生・Workerにも同じ版を接続する。
4. 原因別の境界検査と同条件短期比較を行い、有効性が見えた候補だけ500Tへ進める。前版の同条件v2全Tを基準に使う場合は、設定と旧規則の一致を確認し、別署名の原値を新しい版の成功へ読み替えない。調整済み3条件を独立評価/未使用条件とは呼ばない。
5. 変更箇所に応じた回帰と新旧再生を検査する。前版の619成功を今回の成功数へ転用せず、画像不変部分の500T実画面や全回帰を意味なく繰り返さない。全T原値はgzip・要点は小さい集計へ保存し、毎T全世界や全行動履歴は保存しない。

## 完了・停止・後続

採用差分/有限収支/再現性/新旧保存を確認し、実測をE5/E6、15既存Nodeとcurrent-only Manifestへ反映する。作業結果照合と出力前ゲート後にmainへ統合する。今回の有限な比較が不調なら、失敗を残して効果を認定せず、根拠のある局所修正の完了と全体バランスの未達を分ける。未評価R1〜R6・全端末性能・新Windows/ZIP（I12）を完了扱いしない。

報告はVALIS / READ / TASK / INPUT / NEXT。READは実読したCORE/OTHER、INPUTは必要な利用者入力のみ。承認済み化・正式状態変更は行わない。
