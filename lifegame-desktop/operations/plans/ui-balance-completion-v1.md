# UI・生態バランス完成段階の実行契約

利用者の採用指示と「基本設計・生物・背景は一旦決定稿、UIとバランスを優先」を起点とする。[決定稿](../../design/specification/ui-balance-baseline-v1.md)を作業の基準にし、追加の系統・高度機能の発展は後段へ送る。これは現行製品の完成・正式承認を宣言するものではない。

Operationを先行し、project-local core関連節、現在の仕様索引、採用資料、A1/B5/B5.3/C8/C8.1/D7/D8/D9/E5/E6と現行実装を読み、既存責務で接続可能と判断する。FLOW-04で差分を整理、05で資料/Node/Manifestを反映、07/08で調整前計測の観点と限定証跡を記録する。新規Node分割・正式状態遷移はしない。

今回の実体は決定稿、v5採用表、既存Node参照、調整前計測ツールと結果。計測対象は製品2.3のUIと同じwatershed、40×28、主80体、初期値で5系統、保証補充なし、全生物群が既定で有効、10固定初期値×500ターン。全ターンの不変条件、300〜500連続存続、出生、死因、P/Q数、終端の存続集合、対象ソースのSHA256を記録する。これは各系統10条件・新年齢モデル・新地形方式・新植物の検証ではない。

既存テストを実行し、結果は今回の対象ハッシュに限定する。core・src・製品素材・他プロジェクトは変更しない。過去のEを上書きせず、今回の限定基準記録を既存E5へ接続する。長期バランスを未達のまま成功へ読み替えない。Manifestには現在の採用状態・不足・証跡参照だけを残す。

この区切りの完了条件は、採用4案、元モックに合わせる描画条件、現行と決定稿の差分、調整前結果が一致し、mainへ統合してクリーンになること。次は決定稿の順にUI/地形/年齢/生物差分の実装接続、原因別バランス調整、未使用条件の確認へ進む。各実装単位では関連coreを再読し、C/D/Eの対象版・検査・残項目を更新する。
