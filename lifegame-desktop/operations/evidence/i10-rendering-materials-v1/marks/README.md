# I10 確定行動マークの受領と表示寿命

Linux Chromiumで `tests/action-mark-receipts.test.cjs` を実行。専用38項目、例外0。Node上は1試験成功。`report.json`、`result.json`、隣接の `marks-run.log` を参照する。既存 `display-load-reduction.test.cjs` も1試験成功し、補間/演出/マーク/状態札/年齢/格子/操作中背景の独立性と生態入力不変を回帰確認した。

受領済みキーは表示中マークとは別に保持する。同じターンの段階別イベント、全イベントの確定、refresh、表示切替、停止時の確定状態への巻戻し、同じpreviewの再開で、過去の行動マークを再演しない。後続段階の未受領イベントは同じターンでも新規に表示する。短い演出のON/OFFは静止マークの受領とは独立する。

実アプリの成功した世界生成は `beginWorld(worldGeneration)` で区別。同seed/同設定/同ターンでも別の新世界なら新規受領する。単体rendererではseed/盤面寸法/地形指紋/地形解決値の変化も別世界として扱う。巻戻し検出は保存した前回ターン値を使い、入力オブジェクトを直接更新した場合にも未来マークを消す。

保持上限は直近3ターン×各512キー、表示中256キー、同時描画64件/一個体3種という有限範囲。512キーを超えたターンは受領を閉じ、後続の表示イベントを省略する。キーを古い順に落として再受領する方式にはしない。さらに古いターンを同じ世代で再表示してもマークを再演せず、明示的新世界/再生世代で受領を再開する。検査では700イベント×11ターンを使い、保持1536キー以下と飽和後の再演なしを確認した。これは演出の上限で、生態計算や全ターン観測を省略するものではない。

専用画面は固定した2個体と合成した確定イベントの表示fixtureで、自然な戦闘頻度・500ターン生存・全端末性能の証跡ではない。実アプリの同条件再生成も別途確認した。`marks-received.png` と `marks-new-generation.png` は表示例、`marks-expired.png` は850ms経過後の画面。厳密な有無はJSONの検査結果を参照する。
