## 検査・証跡・再実行

- `node tools/screen-trophic-foundation.cjs custom <出力先>`（lakeも同様）: 初回。design/renewal-screen-v2のallocationのみ。
- `node tools/screen-trophic-habitat.cjs custom <出力先>/habitat`: 適地移動追加。初回runnerを変更せず別ファイルに保存。
- `node tools/audit-water-primary-birth.cjs custom <出力先>/birth`: 200T出生監査。湖も同様。参照元は上記の保存適地移動案。

8条件×501状態＝4008状態で不変条件エラー0。各runnerは製品4.1.3基準の0〜6Tを保存指紋へ照合（重複を除き2設定×7＝14状態）。各試行の観測＋地形cacheは0〜6Tの非観測/非cache世界に一致（8×7＝56状態）。出生監査は400Tすべて保存指紋一致、各条件の最初6Tも非観測に一致。関連13検査はtests.log、参照/階層/core不変はstructure.log。

各jsonは設定/実行hash/最終株量/延べ採食・光入力・葉生成・死因・子孫再繁殖を、json.gzは全ターンを保存。habitat/配下は追加案、birth/配下は出生監査。stocksのland/waterは地形による集計で、生息域を物理的に分断した実験ではない。光入力と可食B生成、採食の移転元Eと実吸収Eを混同しない。原値の浮動小数和を生態系の能力保証としない。
