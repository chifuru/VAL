# 4.2.31 最適化・行動表示の証跡

対象契約: operations/plans/optimization-v4.2.31.md。A/B: design/specification/optimization-v4.2.31.md。正式状態は草案。個体単位、原画35PNG、全ターン原値は維持。集団化は不要として未採用。

## 実装範囲

- 固定地形を深い複製から分離、最良候補の線形選択、繁殖の有効種/疎密候補、B3/S23の有効源からの近傍数集計、Q探索索引の共有。
- 新UIにrandomModel=table/1。4096整数を開始時準備し、用途/turn/個体/候補から順序に依存しない参照。無指定の旧SHAは維持。新署名を保存、異署名の結果を同じ再生と偽らない。
- Workerの段階ごとの一回送信、既存行の変更フィールド/削除キー転送、同一ID順の省略、変化しない配列共有。最終通知までUI確定値は更新しない。
- 時系列の増分キャッシュ、50T栄養フレームの容量計算を新規分だけへ、保存snapshot/ヘッダー/指紋の不要な全履歴複製を削減。
- 影を事前画像化し下に配置。盤面shadowBlur/身体の傾き・押し潰しを撤去、光合成だけの汎用波紋を撤去。元の生物画を保ち、軌跡と実命中/実軽減・850msの作用マークを表示。光/影/マークを共用し、変更のない保持時間は再描画しない。参加種の画像を待機時に準備。Canvas画像容量の推定上限を設定。
- 背景を余白付き高精細画像にし128px単位で再利用。整数画素の位相を保持。六分類の折り返し所在一覧、複数強調/0一覧非表示/独立詳細列を保持。「餌生物」「動く餌」は通常製品UIから廃止。手動stepはsmoke専用。

## 描画計測

browser-baseline.json と browser-table-final.json は同じ小盤面・遠近10Tずつの通常Worker。監視は軽量turn参照。基準近景はフレーム間隔の中央値16.7ms/95%点約100ms/最大約433ms、確定処理最大113.5ms。乱数表/段階画像準備を含む比較は中央値16.7ms/95%点約50ms/最大約350ms、確定処理最大64ms。遠景95%点約83→33ms。

乱数方式により実際の生態経過は異なる。専用PCによる厳密なA/Bではなく、最終フィールド差分/容量管理より前の参考段階も区別する。カクつきの完全解消/全サイズ保証ではない。最終フィールド差分/容量管理後の単独計測（browser-isolated.json）は、近景中央値16.7ms/95%点66.6ms/最大299.9ms、確定処理最大35ms。遠景95%点33.4ms。browser-release.jsonはビルドと重なった試行として区別し、単独性能の根拠へ用いない。最後のマーク上端配置の微修正は同計測後のため、全画素同一条件の保証とはしない。
