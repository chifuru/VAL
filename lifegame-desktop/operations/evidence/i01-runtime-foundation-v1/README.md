対象は基準main `e8488a4`からの開発版4.2.33、実行主体VALIS/Codex、環境Linux x64 / Node v24.19.0 / Chromium。実行契約は[こちら](../../plans/i01-runtime-foundation-v1.md)。正式Node状態/構造とA/B採否は維持。Windows配布済み版4.2.32とは別の対象で、新ZIPは作成していない。

## 実装したもの

- `state.js::withMapScope`が同期区間内だけ索引を共有し、`finally`で必ず破棄する。共有外の`S.maps`は従来どおり新規構築し、初期保証/供給の呼出側が私有Mapを変更できる。
- `engine.js`の移動完了後の効果処理、成長/繁殖、出生後の資源供給の3区間に限定して接続。移動・採食ラウンドの削除・死亡/死骸追加・出生・供給の構造変更を跨がない。共有状態をworld/保存/Worker通信へ追加しない。
- `compute-client.js`で連続turn、要求残数、phase 0→1→2、3段階完備、各meta.turn、予約込み6件上限とidleの整合を検査。不正な現epoch通知は旧確定状態を保持してエラーへ。Workerの要求件数も最大6件へ制限。不正countを拒否する。
- 既存のepoch遮断、途中取消、最後の確定worldからの再init、checkpoint後の継続を保持。全停止問題の修正やI09の操作導線整理を完了した扱いにはしない。
- 静的生成物を更新し、全8優遇設定の22モジュールへ反映。生成物667,204 bytes。生態ソース署名を`e98dd757d22ff53efe5e48637fc2761b692e668e7d70f31421662913e0010712`へ更新した。
- 同値確認した4.2.32署名`8d7f6fbd94128cebf77ab6032098e09a432bc13d8cb2552222b0546971e84745`だけを明示同値とし、既存の旧署名別条件を維持。手動初期数付き旧記録の再生を確認し、未知署名/対応前の旧形式を無条件許可しない。

- 8優遇条件×小40×28・主80・各20T、中80×56・主320・6T、大160×112・主1280・4T。河川・同じ条件・table/1。10条件・初期状態込み180状態。
- 各確定状態のworldが一致。最終指紋と全観測CSVも一致し、各Tの有限収支/不変条件を確認。
