## 13Tで見つけた端数不整合と修正

起点の同条件は13Tで `CELL_ORGANIC` を検出した。有機物のEが0になっても、共有採食の身体量丸め残りB=0.000001が残っていた（マス811、M=0.000001）。E/M総収支は一致していた。[baseline-report.json](baseline-report.json) / [baseline.log](baseline.log) はその反例であり、途中の試行計測を最終値へ合算しない。

`nutrition.js` の新方式の有機物引落しで、身体成分Bを残存E以下へ制限する。身体Bは既にEに含まれる表現なので、E/Mへ架空の加算/消去を行わず、許容誤差も広げない。能力・繁殖・供給・上限等のバランス値は変更していない。微量身体を複数主体で完食する1境界は修正前失敗→修正後成功（[before](rounding-before.log) / [after](rounding-after.log)）。

`cycleExamples` は同マスで組織形成→採食→死骸発生→分解→次T還元→後続の組織形成を順に確認した候補で、4例を保持する。採食源と死骸の個体ID対応や同一養分の粒子追跡をしていないため、単一個体/物質が一周した証明ではない。`production/regrowth` は組織形成の記録で、通常成長と被食後再生を分離しておらず菌も含む。`returned.M` は還元予約量で、実受入量の合計は上記のreturnedMを使う。source/id/speciesの対応がある部分だけを個別に解釈する。

例えばマス756では、T173の草棲虫残骸のIDと、T265に菌が実際に取得した分解元IDが一致する。その後T266に還元が受け入れられ、同じマスの草がB0.178350の組織を形成した。土壌は混合在庫のため、この形成量をその残骸だけの養分へ帰属させない。
