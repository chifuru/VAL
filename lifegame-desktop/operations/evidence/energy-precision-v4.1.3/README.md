製品の履歴/自由/湖3条件と、問題が出た私有候補の負荷条件を各500T確認し、全ターンの段階残差/指紋/個体数/台帳を保存する。既存の固定地形キャッシュを準備し、各条件の冒頭6Tでキャッシュ/観測なしの計算とも指紋一致を確認。負荷条件の最終指紋は、製品反映前の私有修正とも一致させる。負荷条件を製品プリセットや生存改善の採用例として扱わない。

report.json、baseline/*-full.jsonとjson.gz、stress-full.json/json.gz、long-run.log、source-hashes.jsonを参照。baselineは4.1.3の新基準として別保存し、4.1.2の数値へ上書きしない。比較runnerのreferenceRoot/第5引数に基準フォルダを明示でき、異なる版/ソースの基準は拒否する。旧基準の既定実行は4.1.3では拒否される。新基準を使う例:
