# 餌更新・材料循環の候補比較

契約: operations/plans/renewal-screen-v4.1.md。基準はheadless-baseline-v4.1の3固定条件。同じ解決済みconfigと初期指紋から開始し、製品srcは変更していない。無変更3例は0〜500Tの指紋/stats/観測が前回の原値と一致。全18例・各501状態で有限収支/占有等の不変条件違反0。これはR1〜R6合格ではない。

## 候補と結果の解釈

| 候補 | 変更内容 | 判定 |
|---|---|---|
| reserve | 植物/菌類が採食される時にM0.25を留保。補充はしない | 河畔/湖沼で子孫の再繁殖が現れたが、3条件とも終端の餌0。単独採用しない |
| uptake | 土壌Mの一口上限0.1→0.4。残量/上限/吸収効率を保持 | 出生と子孫再繁殖は増えるが、動く餌/植物の終端経路は回復しない。採用保留 |
| sparse | 植物/菌類の出生近傍数1〜5、動く餌1〜3。適地/空き枠/成熟/費用/待機は維持 | 全条件で終端に植物が残るが、動く餌は0。CAの出生密度域の候補として継続検討 |
| combined | 上記3要素 | 河畔/湖沼の主生物は40/34へ増えるが植物0。単独の改善を足しても食物網が改善しない反例。製品へ反映しない |
| reserveSparse | 留保＋近傍出生。combinedとの差は吸収上限だけ | 河畔は主9/植物19/P4、湖沼は主7/植物1/P0、自由は主0/植物7/P3。動く餌/Qは0で、十分な経路ではない |

主生物の終端生存は、主生物が残った全例で植物共生だけ。自由設定の主生物は全候補で0。3条件で一部の個体数や出生が増えたことを、勝者の多様性・全系統の生存ルート・完成した生態系と解釈しない。一次寄生虫の500T存在も、終宿主経由の世代更新が確認できたという意味ではない。

全18例の数表は[table.md](table.md)、機械可読の比較はsummary.json、各候補/条件の詳細は対応JSONと全ターンJSONL.gz。原値を間引かず保存しており、出生阻害や世代/関係/台帳も追える。

## 次の優先課題

1. **水生餌の初期適地配分**: waterbugは全3条件・全候補で初期0、出生0。植物→菌→餌の既存配置順による適地競合と、同群の代替配置を調べる。途中の救済補充ではなく初期配置の契約として扱う。
2. **動く餌の更新経路**: grassbugには出生があるが終端0。植物が残る候補でも動く餌は続かない。次の比較では適地/出生費/摂取・維持/成熟/捕食を分け、寿命延長だけで隠さない。
3. **非光合成の主生物の生存/再繁殖**: 上の餌経路を整えてから、配偶条件/出生費/捕食圧を比較する。植物共生の増加だけでは基本バランスを合格にしない。
4. **P/Q**: 生活環を支える宿主経路が不足。Qの初期数を増やして500T存在を作る調整は先行しない。

3事例の中の因果比較であり、一般の生存確率・全系統・全マップの評価ではない。低競争8/10、混合最低1/10・目標3/10などの正式試験へ進む前に、到達不能/崩壊の詰まりを解消する。

## 実行と証跡

単独比較: `node tools/screen-ecology-renewal.cjs --out artifacts/renewal-screen-v4.1`。
組合せ: 同ツールへ `--variants combined,reserveSparse` を追加する。条件は `--cases custom,river,lake`、短い診断は `--turns` で指定可能。結果は製品図鑑と分離する。

各JSONのsourceHashesは対象ソースと実行ツールを識別する。最初の15例はexecuted-runner-before-pair.cjsがツール実行時の内容に一致し、追加のreserveSparse3例は現在のtools/screen-ecology-renewal.cjsに一致する（差は候補辞書へのreserveSparse追加だけ）。モデルの内容は全例同じ。全出力のhash/ターン連続性を保存時に照合した。

tests.logは専用5検査（無変更一致、未知flag拒否、有償出生、有限土壌移転、空/枯渇時の出生なし、採食M留保）。既存Manifest検査も通過。製品の生態/描画を変更していないため、前段の全テスト/Windows/画面を今回再実施したとは報告しない。
