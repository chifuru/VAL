# 3.2 再読み込み・同品質の軽量化・食性

実行契約: ../../plans/usability-ecology-v3.2.md。仕様: ../../../design/specification/diet-survival-v1.9.md。対象app3.2.0、実体はsource-hashes.json。Linux/Node24.19/Chromium、HTTP loopback。実行主体はCodexによるローカル検査。既存D8/D9に対しE5/E6へ結果を受領する。旧版はf880eb8のsrcをgit archiveで別領域へ抽出し、新旧で同じ設定・初期値を使用した。

## 操作と画面

「地形を選ぶ→世界を作る→観測を開始」を明示。常設の「マップ・初期条件を変更」で一時停止して設定へ戻る。編集は保留し、正常な再読み込みでのみ世界を置換。未保存の観測の扱いを説明し、失敗時は旧世界を保持。初期条件・地形・時間を切り替える実フォームを3回操作して確認。ui-report.jsonとui-reload-settings.pngを参照。個体と図鑑に六つの食性を表示する。

## 軽量化

停止中は同一フレームを再描画しない。200更新要求で追加描画0、強制描画と盤面PNGが完全一致。ui-report.jsonに実測時間を記録する。背景11素材・生物原画10シート・解像度・個体数・ターン計算を削らず、map-report.jsonとhabitat-report.jsonの31/20検査を通過。生態の資源評価・能力評価・最寄り対象の重複計算も省略。食性を変更する前の二条件30ターンでは新旧の生態指紋が一致、計測はmodel-optimization.json。小標本の時間差を一般的な速度保証にしない。

## 生存の変化

草食/肉食/雑食/菌食/腐食/鉱物食併用の消化係数を探索と採食へ共通適用。腐食は死骸を優先。可視の食物への移動と空腹時の捕食評価を加え、満腹時の無益な捕食を抑える。動物性餌を利用する系統が植物も代替食として利用する余地は保つ。無償補充や絶滅救済はない。

10共通初期値×500ターン、40×28/主80/初期5系統/6地形/life年齢。各ターンの台帳・枠不変条件を検査した。主生物全滅は2条件→1条件、300〜500の連続存続の延べ系統数は12→15、全滅を除く終端組合せは7→8。before32-survey.json、after32-survey.json、balance-summary.jsonに初期条件・出生・死因・初回消失・300/500の個体数・指紋を保持。

10総試行は各系統10試行ではない。系統別3/10・最低1/10の目標達成とは扱わず、未参加系統もある。P/Qは両版とも500時点0であり長期維持は未達。全体の完成を宣言しない。調整前後は生態規則が異なるため旧図鑑記録は残し、計算署名の異なる再生を拒否する。

## 証跡の境界

E5: 生態テストと新旧500ターン比較。E6: 再読込み/フレーム再利用・同画質・既存背景/地形操作検査。新規Nodeなし、既存Nodeの正式状態は草案。証跡は対象SHA・依存・入力・検査期待値が一致する範囲で有効。実装・依存・ルール変更で該当部分を再検証する。Windows3.2は対象CIが必要で、3.1成功を流用しない。

比較試作の回帰接続は空白だけの変更で失敗しないよう読み替え側を修正した。規則の欠落/複数一致は拒否し、製品へ試作ルールを採用していない。21製品PNGは3.1とSHA一致。

最終回帰: 103項目の一括検査で製品等102が通過、Manifest1件は検査実行時にE5のunit.logがまだ未生成だったため失敗。その実ログを保存後にManifestを再実行して1/1が通過した（unit.log / manifest-final.log / validation.json）。旧試作の16失敗は読み替え修正後の一括検査で解消済み。現在の未解消検査失敗は0。
