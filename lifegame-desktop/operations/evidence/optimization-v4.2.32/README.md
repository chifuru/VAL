# 4.2.32 一括最適化の証跡

対象: main 1386101を基点とする4.2.32。実行主体: VALIS/Codex、2026-10-19 UTC。契約は `operations/plans/optimization-v4.2.32.md`、仕様は `design/specification/optimization-v4.2.32.md`。FLOW04/05/08で既存A/B/C/D/Eへ接続。core・Node構造・正式承認状態は変更せず、草案を維持する。

## 対象と確認方法

- 背景の既存原画を固定区画で合成し、接続データ/完成背景を再利用。通常経路の画面スレッドで高精細地表を生成しない。背景Worker失敗時は区画ごとの待機処理で復旧する。
- 遠景の同じ記号と静止生産者/分解者の画像を再利用。近景は位置索引で候補を取得。全個体と当たり判定を保持する。新たな画像は待機処理で準備し、初回の背景/外観準備と生態先行計算を順番に行う。
- 可変世界の不要な複製、通信時の全フィールド文字列化、ID索引の再生成、関係/栄養の重複分類を削減。CSV/JSONは小分けにWorkerへ送り、失敗時も観察を継続する。
- 生態の規則・初期数・乱数方式・個体単位・全ターン原値は保持。元画像35PNGと遠景の記号パスは変更していない。

## 生態・保存の一致

`model/parity.json` は旧4.2.31との8優遇組合せおよび小中大の世界/観測/CSV比較。`model/long-run.json` は供給OFFの河川・40×28・主80・乱数表1を500T実行し、有限収支と旧版の全501行を照合した結果。全行一致、最終指紋 `a36bf00ffc8612c562888d7567aa8b5bb8c824c3425aec75b9612585ee4ec0ae` 一致。旧記録の再生互換も確認。条件の詳細は保存済み `model/saved-500.json.gz` を正とする。これは全条件の生存率やWindowsの実時間を証明するものではない。

`unit-initial.log` は開発途中で実施した全53ファイルの成功。`unit-final.log` は最終栄養集計変更後の関連10ファイルの成功。実行時点を区別し、前者を最終ソース全件の結果として扱わない。Windows CIでは製品コミットに対して全件を実行する。

## 配布

ローカルZIP同梱照合と、GitHub Actionsの実Windows起動は別の証跡として記録する。新CIの成功を確認するまでは旧4.2.31の配布実績を4.2.32へ流用しない。実Windows確認後の対象コミット、run/artifact、ZIPハッシュを本節へ追記する。

ローカルのWindows用ZIPは4.2.32、274,737,289 bytes、SHA256 `824e49a70423ce56ef9046e6149c60a8a66156594766782fc4c4fdf3b2ebb67f`。`package-match.json` のとおり同梱src全75ファイル（PNG35を含む）が作業ツリーと一致。実Windows起動の代替とはしない。通常描画500TとWindows CIは実行中で、完了後に別の実測記録を接続する。

Windows初回CI `39338012508`（製品/検査07014cf）は全単体テストと既存画面検査まで成功したが、追加検査のHTTP配信注入が `/app.js` 固定比較でWindowsのパス区切りに対応せず `__R__ is not defined` で停止した。製品コードを変更せず検査のパス比較を `path.sep` に修正し、新CIで全手順を再実行する。失敗時にアップロードされたartifact12228221488は検査ログのみであり、配布ZIPとして案内しない。
