## 変更と測定

攻撃/防御の詳細値に渡すpowerContext.currentと量機同居のS.mainAt参照を、現在選択索引から遅延構築したmain/mainByCellへ接続した。既存の一回のphenotype計算と通常ID追跡索引は維持する。生態用Maps/計算の共有範囲には手を入れない。

同一の小世界で3体を順に選択した場合:

| 対象 | 全Map作成に伴う資源走査（旧→新） | 全資源反復（旧→新） |
| --- | --- | --- |
| 通常主生物3体 | 6→0 | 7→1 |
| 同一セルの相変異量機3体 | 27→0 | 28→1 |

残る1回は既存の現在選択索引の初回構築であり、全資源処理が0になったものではない。量機の数値は3同居体を含むマス全体の詳細を3度表示したケース。主配置Mapは同じ索引内で一度だけ構築して再利用し、主生物の能力/同居表示をしないときは増やさない。記憶量は現在の主生物参照数に比例し、過去状態を蓄積しない。

観測モデルのEcoStateはdispatch Proxyのため、最初のS.mapsプロパティ差替による計数は対象を捕捉できなかった。実際のresources反復を数え、maps/sharedMapsの呼出スタックで全Map由来を区別する計数へ修正した。同居更新の初回試験も、先頭の他個体欄ではなく選択IDの欄を検査するよう修正した。実装をこの試験のために変えてはいない。

## 結果と境界

基点と新appの詳細HTML/全肖像画素/全観測行/fingerprintが一致し、個体配列順も不変。実関数の配置Mapを旧S.mapsと比較し、量機有効時の全同居順と無効時の同セル最終個体規則を保持した。同T明示refresh/個体配列置換/消失ID/別世界、未改変の新世界でWorkerの確定T更新と固定詳細/追跡ID・その所在/手動更新を限定確認した。自然な全移動・死亡・P/Q生活環の網羅試験ではない。

P/Qの専用列挙、全生態計算の索引、世界内データの統合や新しい能力キャッシュは今回追加していない。凍結詳細・記録/保存/乱数/生態/採用画像/グラフ配置を維持する。旧selection-index試験の資源反復数の期待だけ今回の1回へ修正し、旧16項目全体は再実行していない。総合FPS/長期速度・全件・Windows・配布は未測定。正式61Nodeは草案、承認状態遷移なし。次は第6項目、非表示部分の不要処理。
