# CR02：移動・定住・量機の限定証跡

対象は `cell-reorganization/1` の内部移動処理。C7/C7.1/C7.3、D7、E5へ接続する。C8.2は旧署名互換とWorker往復の境界を担当する。通常ターン入口・新方式の図鑑保存は引き続き禁止し、製品設定・UI・配布は変更しない。

## 実装と結果

`node tests/cell-movement.test.cjs`：13/13成功。[tests.txt](tests.txt)。

1. 通常3定住＋2移動。到着Tは空きが生じても定住せず、後続Tの継続滞在で定住する。
2. 定住希望を初期条件/ターン/実IDによる抽選で処理。配列順と既払費用の多さで優先しない。
3. 相変異量機9定住＋2移動。移動中は圧縮せず、拒否された歩は費用0。
4. 壁・予算・総枠不足で途中停止し、成立した経路だけ課金する。
5. 通行不能・種別の適地を維持。動く淡水光合成体は生産者属性のまま4次の移動枠を使う。
6. 通常量機は相に従い1/2/3/4歩、相変異型は全相3歩。
7. 既存の局所行動評価が途中交戦を選んだ地点で停止。接触先実IDを記録し、戦闘後も残り歩数を使わない。行動費は一度だけ支払う。
8. 攻撃前に相手の生存/位置/射程・待機・友好・残予算を再確認。不成立では攻撃費0。
9. 定住満員だけで友好戦闘・追放・4体目の定住を発生させない。
10. 低密度継続でも通常枠に収まらなければ解除待ち。空きができればID・栄養・相・年齢・経験を保持して復帰する。
11. 自発移動後の解除と、Worker/JSONによる所在・移動T・解除状態の往復。
12. 定住できない移動個体は合法な経路があれば移動を試み、全経路が塞がれば待機できる。
13. 生成実行モデルと生成元モデルで、移動・占有・費用・イベント・接触記録が一致する。

`node tests/cell-space.test.cjs`：8/8成功。[foundation-regression.txt](foundation-regression.txt)。旧方式4Tの統計・指紋一致と旧記録の再生互換、各層上限、資源所有、未完成ガードを維持した。

`node tools/build-observation-model.cjs --check`：8プロファイル・22共有モジュール、1,736,284 bytesの生成物と生成元が一致。8条件すべての生存を確認したものではない。

対象ソース・署名は `source-hashes.json`、Node/Core/Manifestの静的照合は `final-check.json`。実行契約は `operations/plans/cell-movement-v1.md`。

## 境界と残件

内部呼出しの少数fixtureによる確認であり、通常観察での新しい生態循環の完成ではない。CR03以降の有限資源配分・維持/出生/分群/分解、途中接触を既存感染資格へ渡す接合、選択/画面/グラフ/新図鑑保存、500T・Windowsは未実施。

移動は1歩ごとにその時点の占有を予約してから確定する。未確定の出発を先取りして満員同士の同時交換を許す方式にはしていない。詰まった個体はそのTの残り移動を止め、次Tに再試行する。定住の調停は既存定住者優先、実際の死亡・退避で空いた場合だけ利用可能となる。

途中の接触一覧は同Tの実ID対を重複排除した一時コンテキストで、全履歴を保存しない。実感染はまだ起こさない。局所交戦は既存の行動評価を使い、異種というだけの攻撃・自動反撃を追加しない。主の密集による攻撃倍率は新方式では付けない。

層索引を移動中の予約/確定/最終照合で共有し、抽選キーは対象ごとに事前計算する。旧経路の意味は維持する。状態・占有・費用・局所判断・署名・生成処理の変更時は関係する境界だけ再確認する。正式Node状態は草案を維持する。
