# I11b 下層の経路診断と限定修正

基準はmain `1b248aa` / 4.2.43。project-local core3の関連制御、A1.2/A1.7、B4.1/B4.4、群落更新・陸水食物網・生存目標の正本、C7.2/C7.3/C7.4、D8/D8.1とI11b契約を実読して接続した。正式状態、A/B、系統、寿命、初期数、造形、UIは変更していない。**この下層診断だけではR1〜R6や長期維持を認定しない。**

## 原因を分けた現行製品の診断

`baseline-diagnosis.json` は生成済み製品の `survival/1` を使い、既観測の固定3条件を50Tまで診断した。監視なし／ありの河川5Tで完全な状態JSONが一致し、3条件全Tの不変条件違反はなかった。出生阻害は延べ個体×Tの重複する理由であり、独立した失敗確率ではない。

- **行動／回避**：草棲虫は移動候補があっても、近接危険の点が移動費に負ける。局所fixtureでは隣接mythの射程内の停止が0.298、射程外移動が0.029で停止を選ぶ。食物がなくても同じだった。河川50Tでは可視主生物の射程内273個体T中265で射程内に残り、45死亡中40が戦闘だった。
- **採食／栄養**：草棲虫は植物由来の有限有機物を実際に食べているが、河川の出生判定312個体T中226でE10未満。移動費を払った後の回復と捕食圧は別問題である。隣接植物Qだけを上げる過去私有案は未改善だったため再採用しない。
- **成熟／待機**：幼体・第一相・出生待機の拒否は存在するが、これだけで途絶を説明しない。相、齢、待機は分離して記録した。資格E10、支払8、成熟条件、待機を今回変更しない。
- **材料／体量**：菌膜は出生にM0.2/B3が必要。一方、任意の胞子放出はM0.1/B2を使う。局所例ではE7.9/B6/M0.2から胞子1回でB4/M0.1となり、次にE8へ回復してもM不足が残る。土壌M5があっても菌膜には土壌取得がなく、隣接鉱物も対象外。同セル鉱物・近傍の実有機物／死骸とは区別する。
- **出生位置**：河川50Tの草棲虫で空き適地なしは1個体T、近傍則による拒否は14、菌膜の空きなしは15。位置だけの問題ではない。湖・森林では近傍則の拒否も多く、全条件を同じ原因にまとめない。
- **被食と任意放出**：菌膜は河川／湖／森林50Tで採食死33/32/33。任意排出32/53/19件には出生材料や体量を割るものが多かった。被食の危険そのものを、留保だけで解決したとはしない。

## `survival/2` に限定した2変更

1. 草棲虫の既存評価に、**見えていて、生存し、待機明けで実予算があり、既存の感知・射程・射線で攻撃できる主生物**の近接危険を加える。移動命令は固定せず、食物・空き・向き・揺らぎ・実費を含む候補比較を維持する。Qや実移動費、他の生物の評価は変更しない。
2. 菌膜の任意胞子／因子放出は、支払後の出生予備B3/M0.2を割る場合だけ見送る。共通の量子化後に判定し、余剰があれば従来費用で放出する。無料の土壌取得、新しい定着、親なし補充、寿命延長、群落化は追加しない。

旧 `survival/1` と版なし経路は保持する。`reproduction.js` のv1/v2ゲート接続はroot担当で、下層担当の実装変更は `behavior.js` と `nutrition.js` のみ。

## 短期の同条件比較と限界

`baseline-50.json` と `combined-50.json` は、rootのv2初期齢・寄生処理を共通にしたsource factoryで、下層2変更のOFF/ONだけを比較したもの。**v1製品とv2製品の比較ではない。** 共通の実ロードP SHAは双方 `ba733566…`。各runで要求・実効設定、実初期数、全50Tの集計・死亡・子孫、実ロードsource SHAと5T監視一致を残した。

| 条件 | 草棲虫50T OFF→ON | 草棲虫出生 OFF→ON | 菌膜50T OFF→ON | 菌膜出生 OFF→ON |
| --- | ---: | ---: | ---: | ---: |
| 河川 | 0→0 | 14→5 | 6→4 | 6→8 |
| 湖 | 0→7 | 20→26 | 6→5 | 9→9 |
| 森林 | 7→2 | 33→33 | 0→0 | 1→1 |

回避行動と留保は成立したが、個体群の改善は一様でない。草棲虫は回避の実移動費も負担する。死亡の絶対件数が減ったことを、暴露時間や個体数を揃えた危険率改善に読み替えない。出生圧の拒否はE不足などと重なるため、件数だけで出生圧を緩和しなかった。菌膜の採食による消失、材料・有機物の所在、草棲虫の更新は残件である。

この3条件比較のbehaviorは、射程2の自己遮蔽修正前のSHAに限定する。提案時の `wouldLoseBirthMaterial` は丸め前の参考計数であり、候補の少数の境界誤差を実支出後の留保違反と解釈しない。実処理は `S.round` 後のB/Mを判定し、境界テストで検査した。

### 射程2の修正と再測定

レビューで、移動本人の元セルを射程2の遮蔽として残す不整合を修正した。本人だけが離れる場合はそのセルを除き、同セルに別主生物／別一次消費者が残る場合は遮蔽を維持する。

`ray-fix-comparison-50.json` は、この修正だけの前後を共通source・河川50Tで再測定した。P/state等のロードSHA一致を検査し、修正前後の最終fingerprintは双方 `ba6cb6f2…`、出生・死亡・各Tの個体数は同じだった。この50Tでは該当射程2の差が結果を変えなかった。新規境界fixtureでは本人だけの元セルと、別個体が残る場合を独立に検査した。

修正後behavior SHAは `dc5be816…`、nutrition SHAは `bc2a5a1c…`。全9専用検査が通過した（`unit.log`）。最終製品のv1/v2・3条件500Tはroot側の新署名計測へ接続し、この50Tから結果を補完しない。

## 証跡・再現・採用しない試行

- `diagnose.cjs`：現行製品v1の監視付き原因診断。`baseline-diagnosis.json/.log` を出力する。
- `compare.cjs` / `source-model.cjs`：共通source固定のv2下層OFF/ON比較。`comparison-50.json` は要約。
- `comparison-source/`：この私有比較で**実際にロードした11の生態ファイルだけ**を保持。rootの未コミットだった共通v2条件を固定するために必要だった。renderer/transport/Worker/表示等、未ロード16ファイルは削除した。`source-sha256.json` に固定時刻・使用SHA・削除対象を記録する。
- `before-behavior.js` / `before-nutrition.js`：下層変更OFFの固定入力。1b248aaと同じ実装で、比較でのみ使用する。製品に組み込まない。
- `compare-ray-fix.cjs` と `ray-*.json`：自己遮蔽修正前後の限定再測定。実ロードsource SHAを保存した。
- `pre-freeze-unreliable/`：最初の4要因試行は、PのロードSHAが記録されず共通Pを保証できなかったため採用比較から除外した。理由を `STATUS.json` に記載し、成功例へ差し替えたことにしない。速度の概算以外の根拠には使わない。

50Tの直接計算は通常1条件約8〜12秒。自己遮蔽再測定の14.6/30.0秒はrootの並行負荷中の参考値で、モデルの速度差とはしない。保存・描画・5〜15分再生目標の認定ではない。
