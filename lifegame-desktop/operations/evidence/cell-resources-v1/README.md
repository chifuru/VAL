## 実体と計算上の具体化

- `state.js`のCellSpaceが固定環境/土壌/在庫設定、身体M、還元待ち/有機物の所有を保持する。soilMが唯一の無機在庫。身体Bに含むEと、保持Mを別勘定にする。初期の身体Mの割当はCR04の初期化で接続する。
- `nutrition.js`のCellResourcesが準備・要求配分・実移転・維持支払・予約/取消/形成を担当する。`engine.prepare`の新方式分岐はこの準備へ接続し、出発地点で先に光合成しない。
- 内部順序はprepare→移動/戦闘→実行費支払→acquire→settleBudgets→任意予約/確定。要求生成器はCR04/05が実際の種別・相・身体・不足量から作る。今回のfixtureは明示要求による境界確認で、自律生存の観察ではない。
- 純粋な配分は必要量×相対取得能力×到達性を重みにし、上限と不足資源で打ち切った残りを再配分する。実取得の最大量はlimitで別に制限する。世界の処理は同マス単位に分け、全盤面の要求を全対比較しない。
- 気温/pH曲線は採用表を区分線形補間。陸の蒸発は20℃で0.5、10℃変化で2倍/半分、倍率1/16〜16を比較開始式とした。これは追加気候機能や観察済みの自然定数ではない。
- 光合成E/水分は2.6/1。水分支払は同マスの合計で最小単位へ切り上げ、実在庫を超えない。食物/配分の微小端数は在庫に残し、食物量を使い切った残余は次T有機物へ渡す。固定IDへ端数報酬を集中させない。
- 食物の同化率は現行の食性処理を使用する。未同化分は次T有機物、維持Mは次T還元待ちとした。身体形成の余剰Eは熱へ。今回だけで分解・繁殖の意味を置換しない。
- 明示0次入力はledger.cellInputMへ分離。水系は専用値未選定のため供給計算を見送り、利用に必要な場合は未解決として拒否する。
