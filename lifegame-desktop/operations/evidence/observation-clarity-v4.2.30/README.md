# 4.2.30 観測・描画・個体群調整の実測

比較元main7fd7582/4.2.29。原画・遠景記号は維持。初期Qと出生調整は生態条件を変えるため署名更新。正式状態は草案。4.2.29の500T結果を新版へ流用しない。

## 実装

- 停止/再開ボタンのラベル誤りとframeによる「準備/計算待ち」上書きを修正。最初の計算済みターンから表示。60秒無応答等の停止は維持して理由を区別。
- 円グラフ100→180px、3グラフの列420→480px。個体選択時も全期間3グラフを隠さず、隣の独立列へ詳細を表示。層分離はOFFで通常UIから撤去。関係図の枠間10→50。
- 下層合計を「餌生物」と呼んでいたため「下層生物」へ訂正し、生産者/一次消費者/分解者の内訳を表示。
- 自動初期QはPの半数（優遇OFFは旧目標との小さい方）。例: viewport-reviewはP18/Q128→P18/Q9。手動数指定は尊重。Q総数は探索を含み、経過中の大小を強制するものではない。
- 新UI生成はpopulationRegulation/1を明記して保存。一次消費者の初期密度10→6%。主/一次消費者は局所混雑と栄養/蓄えで出生確率を下げ、低密度の一次消費者は抑えすぎない。成熟/配偶/費用/出生先は必須。全個体を強制削除する上限は付けない。
- 近景背景を固定地形だけ受け取る描画Workerへ。生成中も操作/生態を続け、低解像度の既存表面から同じ高解像度結果へ差し替える。古いカメラの結果を破棄。非対応時は旧経路へ戻す。地物の影を小画像キャッシュ化。静止生産者/菌の不要な視界/得点計算、グラフ二重更新を省く。
- 生物の物理的な群体化は未実装。今回判明した画面負荷へ描画側を先行し、計算上の個体数増大は出生調整で対応する。未採用案はdesign/proposals/lower-population-aggregation.md。

## 描画計測の範囲

performance/browser*.jsonは同じ小盤面・主80・通常Worker・遠近各10T。監視ではsnapshot全体を毎フレーム複製せず、軽量なturnだけ参照。

旧近景の最大draw2443ms→背景Worker導入時453ms。さらに影キャッシュ後のフレーム間隔中央値は旧100ms→16.7ms。ただし最大間隔は約517ms、95%点約117msが残り、遠景の中央値も17〜33msに揺れる。代表環境の参考値であり全PCの滑らかさ/倍率を保証しない。各試行は逐次だが厳密な専用ハードウェア比較ではない。

静止生産者の直接処理は2初期値×20Tで同じ生態指紋/収支。行動選択の累計約1353〜1372→1060〜1097ms。全体改善は0〜10%程度で、これだけをカクつき解消とは扱わない。

## 個体群の比較

供給ON/河川40×28/主80/2初期値、全ターン収支検査。調整前100Tは主144/125、一次消費者702/623。採用案は主114/100、一次消費者132/55。初期一次消費者は111/112→67。performance/populations-final.jsonを参照。

強すぎる初案は片方の一次消費者を4体へ減らしたため不採用。弱い案も一方で200Tに597体を残したため採用案とは分ける。500T代表確認はperformance/populations-500.json。両初期値で有限E/M収支に違反なし。主122/81、一次消費者94/66が存続。100T以後の主個体数は一方が162まで増えた後122へ、他方は59まで減った後81へ。Qは0/241で異なる結果。全条件・全系統の存続率/最終勢力の多様性は未認定。
