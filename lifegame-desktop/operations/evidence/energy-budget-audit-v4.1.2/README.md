# 4.1.2 エネルギー残差の原因監査

契約: operations/plans/energy-budget-audit-v4.1.2.md。基準コミット977da71の生態ソース。旧私有候補allocationLocal/historical-inputを係数変更なしで段階別観測した。report.jsonのmatchedStates484は0〜482Tと既知の失敗483Tの保存指紋一致。484T以降は診断継続であり、失敗を通過へ変更していない。

500Tの残差0.002140の内訳は行動費の支払いN.payActionsで0.002067、prepareを含む区間で0.000073。他の観測した区間の累積差は0。全ターンの区間差/指紋/ゲート結果はstages.json.gz。許容値0.002は維持。

費用0.1465605、保有E1を旧spendで支払うと、保有E0.853440と散逸0.146561の合計が1.000001となる。個体から引く量と散逸へ足す量を独立に丸めたため、取引ごとに微量を生成していた。支払費用を6桁に確定してから同じ量で両側を処理すれば生成しない。植物16体、光量0.10000015625、B8の小さな再現例でも光入力と受取の累積差0.000002を確認し、入力の先行量子化で解消する。

私有修正はこの2箇所だけ。private-fix.json/private-check.logでは同じ失敗候補を500Tまで実行し、全ターン/全観測区間の残差0、収支/占有検査を通過。原文はprivate-fix-source.cjs.txt（当時の実行環境パスを含む保管用）。その後の製品4.1.3と同じ候補の最終指紋も照合する。適地配分・局所更新の候補は負荷条件として使っただけで、製品へ採用しない。

段階観測の状態一致/例外時フック復元と、小額費用/不足費用/半端な光入力の回帰はtests/energy-budget-audit.test.cjs、audit-tests.log。旧ツール原文screen-before.cjs.txtは4.1.2比較runnerの保管用。新しい製品の検査は../energy-precision-v4.1.3/README.mdへ分離する。
