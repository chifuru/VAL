# I11 主生物・下層繁殖の診断と最小候補

状態：候補実装・固定条件の比較まで。**R1〜R6 全体は未達として保持する。バランス回復・承認済みとはしない。**

## 比較条件と実装範囲

- 基準：`af9ae14da7e22d3ae50b5571f053b68c79fc22b2`、製品 4.2.42 の生成済み観測モデル。
- 候補：同じ advantage-switches モデルを現行 source factory から生成し、`balanceModel: survival/1` を付与。I01〜I09 と優遇3項目は全て有効。モデルごとの要求・解決済み設定は各 JSON の `request` / `resolved` に保存した。
- 40×28、初期主生物160、選択主系統7/5/7、河川・湖・森林の固定3条件。seed / terrainSeed は採取前に固定し、成功した条件への選び直しは行っていない。初期下層密度・資源・生産者供給も記録済み設定を使用し、救済補充は加えていない。
- `reproduction.js` の候補は、低い全体主個体密度（通行可能マス当たり20%未満）で通常有性出生の近傍を2〜5、有精女王の近傍を1〜5へ緩和する。密度が高ければ従来の2/3近傍を維持する。主生物出生圧の目安を16%→20%、過密抑制の傾きを8→4とし、実資源による係数・乱数・費用・空きマス・親の条件を残した。
- 草棲虫は既存の1親更新のまま近傍1〜3、資格E10、支払8。寿命・HP・栄養会計・菌膜は変更していない。`nutrition.js` は無変更。
- 候補計測には別担当の `survival/1` 寄生変更も含む。繁殖だけの要因分解実験ではない。

## 結果

値は「基準 → 候補」。各 run の全500Tで `E.invariants` を検査し、候補合計1500Tで違反はなかった。

| 条件 | 主個体100T | 主個体250T | 主個体500T | 草棲虫の累積出生 | 草棲虫100T | 草棲虫500T |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 河川 | 180 → 196 | 138 → 160 | 69 → 73 | 8 → 12 | 0 → 0 | 0 → 0 |
| 湖 | 201 → 211 | 188 → 196 | 73 → 124 | 36 → 47 | 0 → 0 | 0 → 0 |
| 森林 | 165 → 180 | 148 → 162 | 78 → 62 | 26 → 37 | 0 → 3 | 0 → 0 |

合法的な出生と初中期の更新は増えたが、終盤の改善は一様ではない。河川の光合成系・結晶系、湖の漂遊系が増えた一方、森林の主総数は減った。湖の深殻系や河川の真社会系などは候補で終盤0になった。系統別・直近50Tの出生は `paired-comparison.json` に記載した。

草棲虫は河川で45死亡中40が戦闘、3が採食であり、出生緩和だけでは捕食圧に追い付かなかった。湖は80死亡中53が加齢、26が戦闘、森林は70死亡中53が加齢、14が戦闘だった。森林では9世代まで実際に更新したが少数化して途絶えた。加齢死が多いことだけを根拠に寿命を延長しない。

菌膜は候補500Tでも3条件全て0で、出生は5/11/1。初期に採食で大半を失う点が残る。P/Qも全条件で500T終数0であり、これらの長期維持は証明していない。

500Tの診断全体時間は河川85→81秒、湖89→119秒、森林93→119秒。後半2条件は生存個体数・関係記録量や実行環境の同時負荷も異なるため、この比較を単体の性能改善率には使わない。

この3条件では150〜250Tの25Tごとの記録に全選択主系統が存在した。ただし、既に観察した診断seedであり、同一条件10seedの生存率・holdoutではない。異なる参加系統の3条件を、同一条件での終盤パターン多様性3件として数えない。R1〜R6合格の根拠には不足する。

## 後方互換と検証

- `balanceModel` を付けない source factory の固定3条件100Tは、基準製品の最終fingerprint・最終統計・25Tごとの観測snapshotと全て一致した。証跡は `legacy-parity-100.json` と `legacy-parity-result.json`。
- 旧 `reproduction.js` を同じ状態APIへ差し替える専用検査でも、3地形各8Tの完全な状態JSON・乱数結果が一致した。
- 専用7件は、2親／保存父系、実E/M支払、幼体・待機・壁・過密による拒否、草棲虫の有限出生、栄養依存の出生圧と旧経路を検査した。
- 既存の繁殖・年齢検証と合わせた24件が全て通過した（`regression.log`）。

## 次の有限な調整候補（未実施）

1. **草棲虫の捕食回避と更新**：河川では、既存の脅威評価・移動先が実際に逃避へ結び付くかを局所fixtureで測る。湖・森林では成熟後に食べてE10へ戻るまでの時間と出生圧・空き場所・待機の拒否を分け、1項目ずつ比較する。無親補充・寿命だけの延長は行わない。
2. **菌膜の再定着**：初期採食で失われる量と、実在死骸から得るE/M・成熟・合法出生の不足を分けて測る。残存基部や定着時機を変えるなら仕様上の扱いを明示し、無償の群落再生成にはしない。
3. **P/Qの生活環全体の更新**：Pは実際の放出・感染機会・費用・再放出、Qは限られたPの成熟窓・羽化費用・自立後採食を遷移別に数える。段階ごとの成立を先に確認し、数の救済や感染窓の無制限化で帳尻を合わせない。

いずれも、少数の固定fixture／短期比較で原因を確かめてから、事前宣言した評価seedへ進む。追加の調整・重い試行はこの診断では行っていない。

## ファイルと再現

- `baseline-100.json` / `baseline-500.json`：基準の各run・各ターン所要時間・死因・出生阻害・25T snapshot・最終fingerprint。
- `candidate-500.json`：候補の同じ全量と起動時source SHA。`candidate-100.json` は同じ500T実行の100T checkpointで、独立した再試行ではない。
- `paired-comparison.json`：系統別終数／出生、最後50Tの出生、下層の世代記録を含む比較。
- `source-sha256.json`：基準commitのsource SHA、候補の計測時source SHA、記録ファイルSHA。基準はGit objectから採取した。
- `before-reproduction.js`：旧経路専用テストの固定fixture。過去の再現用であり、現行実装ではない。
- `diagnostic-runner.cjs`：相対パスへ可搬化した採取runner。数理・seed・設定・更新ループは採取時と同じ。`I11_VARIANT=baseline` はそのcheckoutの生成済み製品、`legacy-parity` はflagなしsource factory、`candidate` は `survival/1` source factoryを使用する。

プロジェクトルートから、既存証跡を上書きしない出力先で実行する：

```sh
I11_VARIANT=candidate I11_TURNS=500 I11_OUT=operations/evidence/i11-survival-performance-v1/breeding/recheck node operations/evidence/i11-survival-performance-v1/breeding/diagnostic-runner.cjs
node --test --test-isolation=none tests/survival-breeding.test.cjs tests/ecology-reproduction.test.cjs tests/age-model.test.cjs
```

基準の厳密な再採取は `af9ae14` checkoutの生成済み製品で行う。後日のsourceで候補を再実行する場合、まず保存済みSHAとの一致を確認する。設定・seed・観測量は本ディレクトリに保存されており、一時ディレクトリ内のファイルを必要としない。
