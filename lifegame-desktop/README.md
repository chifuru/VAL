# LifeGame — 生態シミュレーション 4.2.35（I03開発版）

開発版4.2.35は森冠・星冠・移動する淡水光合成体を独立した生産者として加えるI03の更新です。有限な光・土壌養分・可食部を使い、年齢成熟による繁殖と実績による相成長を分けます。配布済みWindows版は下記の4.2.32で、開発版のWindows検証・新ZIP配布はまだ行っていません。

固定8環境で、生物・群落と有限資源の食物網を観測するWindows向けローカルアプリです。新しい世界は34系統、旧モデルの記録は従来の31系統を保持します。同じ初期値と設定から同じ世界・結果を再現します。

[4.2.35の独立植物・保存・限定検証](operations/evidence/i03-independent-plants-v1/README.md)を参照してください。固定条件で基本循環を確認し、全系統の500T生存率/最終バランスは継続調整です。

4.2.32は背景の固定区画・遠景の静止表示を再利用し、近景を位置索引で検索します。画像加工の作業領域を共有し、全期間CSV/JSONを分割してWorkerで出力します。開始時は背景・外観を準備してから計算へ進み、準備全体の上限は60秒です。[今回の実測と制約](operations/evidence/optimization-v4.2.32/README.md)を参照してください。

継続する改善として、開始時の乱数表、計算/通信/グラフ/保存の重複削減、事前生成した陰影と高精細背景の再利用を接続しています。身体の微細な変形に代えて、実際の行動を短いマークと軌跡で表示します。生物一覧は分類ごとに折り返し、通常の1ターン確定操作を撤去しました。[4.2.31の実測と制約](operations/evidence/optimization-v4.2.31/README.md)を参照してください。初期密度と出生調整は4.2.30の方式を維持します。

生産者・水游虫・高次寄生の優遇は初期設定で個別にON/OFFできます。生産者の環境供給も自由設定で選べます。動物・寄生虫の救済補充はありません。全初期値の安定率、菌膜の後期存続など細かなバランスは継続調整の対象です。

地形は蛇行河川・湖沼・湿地・岩地・疎林平原・盆地の事前地形。候補地点の地物だけを変え、固定環境と変動する生物を分けます。遠景は記号、近景は専用原画と景観です。[採用モック対応表](design/specification/ab-visual-reference-v1.md)を維持します。

## Windowsで起動

[4.2.32 ダウンロード画面](https://github.com/chifuru/VAL/actions/runs/39340183030/artifacts/12229435734)から **LifeGame-Windows-x64** を取得してください。Windowsでの実行確認済みです。外側のZIPを展開し、同梱の `dist/LifeGame-Windows-x64.zip` も展開して `LifeGame.exe` を起動します。DLL・resources・localesは同じフォルダに保ち、アプリ下部の版表示を確認してください。

Windows 10/11 x64用。利用時にNode.js・ネット接続・外部サービスは不要です。実行中の観測状態は終了時に消えます。明示終了または主生物全滅で保存した最終結果は、配布物と別のローカルアプリ領域に最大100件保持します。実測対象・環境と制限は[現行Manifest](valis/summary/lifegame-desktop.summary.md)とEノードに記載します。

## 観測する

1. 初期設定でモード、地形、大きさ、生物数、系統、配分、配置、参加生物群を選びます。内部初期値は自動生成し、通常画面には表示しません。固定モードの調整条件は開始前に明示します。
2. **この設定で世界を作る**で初期状態を準備します。この時点では時間は進みません。
3. **観測を開始**、一時停止、再開で操作します。500ターンごとに一時停止し、その後も続行できます。主生物全滅時は最終結果を保存して終了します。
4. 盤面をクリックするとマス内の主生物・一次消費者・寄生階層・資源を観察できます。ドラッグで移動、ホイールと＋/−で拡大縮小、**選択地点の近景**で表示範囲を絞り、**全体**で全盤面に戻します。画面外の計算は止めません。操作・詳細・説明の閲覧中も進み、手動停止中は時間を止めたまま観察できます。
5. **系統樹・説明シート**から全系統の分岐、餌、戦闘、繁殖、寄生、情報を確認できます。図鑑を開いても自動停止しません。

**終了して図鑑へ保存**で初期条件・最終状態・全ターン集計を保存します。途中の一時停止では保存しません。**結果図鑑**から同じ初期条件を再計算でき、再生の完走・中断・反復では記録を追加しません。「再生結果を新規保存」を押すと元記録を残して新しい記録を保存します。計算版が異なる記録は再生を拒否します。上限に達したら不要な記録を削除し、保存失敗時は再試行できます。

小40×28（主80体）、標準80×56（320体）、大160×112（1280体）。各マスに主1体・生産者/分解者1体・一次消費者1体の3枠が共存でき、寄生虫Pは宿主、高次寄生虫QはPに付随します。画面外も計算します。表示は点・簡略・詳細を倍率で切り替え、負荷時には実時間の進行を下げます。基準速度は1ターン約1秒、三段階表示。負荷が高いときは省略せず減速します。手動の1ターン操作は通常画面にはありません。

## 世界を切り替える・見つける

**初期設定へ戻る**は進行を止めて設定画面へ戻ります。実行中に初期条件を編集する方式ではありません。新しい世界では同じ設定でも配置を再生成します。**同じ世界をやり直す**は元の初期条件を使います。未出力の履歴を破棄する場合は確認を表示します。

「盤面の記号と現在の個体数」のチェックで系統の所在を強調します。複数系統を同時選択できます。記号・名前・個体数のボタンは生物説明を開きます。植物・一次消費者・一次/高次寄生虫も対象です。選択した個体の **選択個体を追跡** で同じIDを追い、寄生虫は宿主位置を追います。ドラッグはカメラ追跡だけを解除し、死亡/消失時に別個体へ自動切替しません。

## 初期数の個別調整

「下層生物・資源の初期量と分布」内の「種別の初期個体数・寄生群体数」で指定できます。空欄は自動、0は初期配置なし。寄生虫は群体単位で宿主が必要です。種別数を指定する場合は初期餌保証をOFFにしてください。配置不足は設定画面で案内し元の世界を保持します。開始後は「種別の初期配置結果」で指定/実配置を確認できます。供給・出生・感染は開始後も通常どおりです。[詳細](design/specification/founder-counts-v1.md)。

## 全ターングラフとCSV

上部の統合サマリは現在像、右側の個体数の積み上げ・集団構成・生態関係の三グラフは全期間を示します。選択した個体の詳細は右の独立欄に表示し、三グラフは常に残します。0ターンから現在まで各ターンの実値を保持し、500ターンを続行しても古い点を削除しません。参照ターンの入力とグラフの指示で過去の実数を確認できます。表示用の要約と元データは別です。

新たな接触回数、接触が続いた組ターン、捕食・感染・支援等の成立回数を分けます。寄生が30ターン続いたことを新規感染30回と数えません。系統間の継続関係は直近50ターンの完了した10ターン区間で観測し、その各ターン値も全期間保持します。

**全ターンCSVを保存**で実数と分母、系統ID、モード/実際の初期条件/内部初期値/計算版を出力します。保存先でファイルをご確認ください。容量上限では古い記録を捨てず停止して出力を促します。閉じると未出力のセッション履歴は失われます。CSVは最終結果図鑑とは別の明示出力です。主/餌は個体、P/Qは群体の管理単位であり、合計はバイオマスではありません。期間ズームや栄養網深度等の補助表示は未接続です。

## 生態モデル

- 基本20系統はI→II→IIIの3枝→IVの各2枝。追加の早成甲殻は三相、植物・菌・動く餌は二段階です。子は必ずI相から始まります。
- 光→植物→動く餌→主生物→死骸・菌・土壌の有限収支。植物は刈取りで基部を残し、有限土壌から材料を吸収します。有性出生は二親を要する近傍2〜3体。鉱物・情報の候補にはB3/S23の局所CAを使い、供給元の予算も必要です。
- 行動は9つの重みと局所刺激の評価結果です。固定の「群れ戦略」を選択せず、実成果・仲間接触・情報が重みを変えます。同系統は仲間です。
- 有性繁殖は相によらず年齢成熟後。浮遊傘の兼性単為生殖、群体節足の繁殖分業・共同育児を含みます。
- 寄生虫の第一/中間/追加中間/終宿主の生活環、高次寄生虫の限定感染窓と行動/情報への間接操作を扱います。
- 情報は**延長された表現型**の抽象モデル。鮮度・文脈・撹乱があり、DNAの水平伝播は行いません。新鮮な局所経験をB3/S23の潜在場に使い、有限Eを支払って情報餌を生成します。消滅後も経験から再発生できます。[生成と受容の仕様](design/specification/information-experience-ca-v4.2.29.md)。

仕様の差分正本は[生態・観察A/B v2.4](design/specification/ab-ecology-observation-v2.4.md)です。13節に4.1の調整条件・実装範囲と未達、[仕様索引](design/specification/README.md)に基礎仕様との優先関係を記載しています。

配布確認済みの4.2.31はCI39300201408でWindows ZIP生成・全展開チェックサム・実exe・生態Worker・背景Worker・画像読込・Node非公開を確認済みです。代表条件の通常500Tは約9分2秒、全501行の図鑑保存と描画なしの最終指紋一致を確認。[今回の実測](operations/evidence/optimization-v4.2.31/README.md)を参照してください。全条件の生存率や全PCの性能保証とは分けます。

## 開発・検証

Node.js 22.12以上（CIは24）。

```sh
cd lifegame-desktop
npm ci
npm test
npx playwright install chromium
npm run test:browser
node tests/ecology-observation-ui.cjs
npm start
npm run test:desktop
npm run package:windows
```

Linuxのブラウザは `CHROMIUM_PATH=/usr/bin/chromium` などで指定できます。画面検査はHTTPループバックで行い、配布アプリはElectronのローカルfile表示・Node非公開・外部通信遮断を使用します。Windows CIはZIP全展開後にSHA256を照合し、実exeを起動して進行を確認します。旧 `src/model` / `tests/engine.test.cjs` は旧版の回帰対象であり、現行生態モデルの検証根拠とは分けます。

## 計算モデルを変更する開発者向け

選定モデルの実行コードは `tools/build-observation-model.cjs` で静的生成し、`tools/update-replay-version.cjs` で計算版を更新します。モデルの変更後は両方を実行し、比較モデルとの一致とWorker/保存再生を確認してください。4.1.3固定証跡を使う旧比較実験は同版のソースでのみ実行し、新製品へ証跡を付け替えません。
